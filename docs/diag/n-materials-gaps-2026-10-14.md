# 새 정보 재료(N1~N7) — 원문 공백과 판정 보류 (2026-10-14 밤)

리드 점검에서 판정에 닿는 결함이 하나 나왔고, 같은 꼴을 N1~N6 에서 훑었다. 도구: `tools/build_n_materials.py`.

## 1. N7 판정 보류 — 재료가 불완전했다

- N7 은 **신탁 해지결과(bb_trust_end) 원문 0/1,612** 상태로 구워졌다(`events.parquet`·`N7.parquet` 10-14 08:58, 이후 재굽기 없음).
- `n7()` 이 파싱된 사건만 쓰고 `fillna(0.0)` 했으므로, 원문이 없는 신탁 해지가 **'이행 0'** 으로 읽혔다.
  - `pred`(실제 취득, 반감기 60): 신탁형 매입이 빠져 덜 세였다.
  - `x_unfilled_h60`(결정 − 이행): 신탁형에서 결정만 있고 이행이 0 이라 부풀었다.
  - 도구 자신의 규칙("결측은 0 이 아니라 `m_*` 표지")을 어겼다. N1(리픽싱)·N3(담보·소유 변동)에 있던 80% 원문 관문이 N7 에는 없었다.
- 따라서 **N7 의 16:52·22:10 사다리 판정(② ΔIC +0.0006, t 3.40 포함)은 무효 — '보류(재료 불완전)'**. 원래 결과 파일·원장 줄은 지우지 않는다.

### 고친 것 (브랜치 `n7-trust-gate`)
- `n7()`: 신탁 해지결과 원문이 80% 미만이면 **굽기를 거부**(N3 담보와 같은 꼴). 80% 를 넘어도 **파싱 못 한 해지결과**가 최근
  60세션 안에 도착한 (종목, 세션)은 `pred`·`x_exec_250`·`x_unfilled_h60` 을 결측으로 두고 `m_trust_gap`=1 로 표지.
- `backfill_n_texts.py`: 우선순위를 **신탁 해지결과 → 담보 → 조정 → 소유 변동** 으로(일 상한 1,500 그대로). 10/14 밤 남은 양:
  bb_trust_end 1,620 · refix 3,850 · holder_change 11,646 · pledge 0. 크론(평일 19:20, main 트리)이 읽으므로 머지 뒤 1~2일이면 끝난다.
- 회귀 테스트: 원문 없음 → 거부, 파싱 실패 → 결측·표지(0 아님), 백필 첫 순위.

### 남은 일
커버리지 ≥ 80% → `build_n_materials.py features --n N7` 재굽기 → 사다리 재판정(10/22 전). 재굽기는 재료 파일이 바뀌므로
`plus_cache_path` 키(크기·수정 시각)가 달라져 캐시를 타지 않고 다시 배운다.
