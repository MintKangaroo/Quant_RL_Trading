## 1. N2 — 정기보고서 원문 비용 확인

### 1.1 방법

- 기존 배관 그대로: OpenDART `corpCode.xml` → `list.json`(`corp_code`, `pblntf_ty=A`, 1999-01-01~2026-10-10, 100건/쪽) → `document.xml`(ZIP).
  디코딩·평문화는 `quant_rl_trading/collectors/dart_documents.py` 의 `decode`·`to_text`·`extract` 를 그대로 썼다(euc-kr 선언/UTF-8 바이트 함정 포함).
- 표본: `corpCode.xml` 의 종목코드 보유 회사(상장폐지 포함) 중 **무작위 60개**(seed 20261011). 1개는 정기공시 0건.
  - 사업보고서 원본(정정 표지 없는 것) — 접수 연도 2015·2018·2021·2024 전 표본, 2005·2010 은 앞 15개, 2025 는 앞 12개
  - 최신 분기보고서 원본 하나(상장폐지 회사는 그 회사의 마지막 분기보고서라 2007~2026 에 흩어짐)

- **기존 저장 형식(평문)에서도 된다**: `extract` 평문에 줄 정규식(`^[IVX]+\.` + 목차 중복이면 가장 긴 구간)만으로 사업의 내용 228/228, 투자자 보호 223/228, 사업보고서 MD&A 159/170. 즉 이미 `data/_docs/dart` 에 받은 정기보고서는 **다시 받을 필요 없이** 섹션을 잘라 쓸 수 있다.

### 1.5 유사도 계산 가능성 시연 (수치 해석 안 함)

같은 회사 직전 동종(사업↔사업) 12쌍 × 섹션 2개(사업의 내용·투자자 보호), 한글/영문 2자 이상 토큰의 단어빈도 코사인·자카드. **24 비교에 0.08초** — 10만 쌍도 CPU 몇 분. 모든 쌍에서 값이 나왔다(빈 섹션 0). 값은 0.26~0.98 범위로 퍼져 있다는 것만 기록(의미 해석은 등록 뒤). Lazy Prices 원 설계대로 분기는 **전년 같은 분기**와 비교해야 하므로 회사당 최소 5개 분기 이력이 필요하다.

`BAS_DD` 기준일 · `PROD_NM` 상품명("삼성전자 선물") · `MKT_NM`(정규) · `ISU_CD` 종목코드(선물 코드, 예 `111V1000`) · `ISU_NM`(예 "… F 202403", 스프레드는 "… SP 2403-2406") · `TDD_CLSPRC`·`CMPPREVDD_PRC`·`TDD_OPNPRC`·`TDD_HGPRC`·`TDD_LWPRC` · **`SPOT_PRC`(기초자산 현물가)** · **`SETL_PRC`(정산가)** · `ACC_TRDVOL`·`ACC_TRDVAL` · **`ACC_OPNINT_QTY`(미결제약정)**.

- **권한: 있음.** 두 서비스 모두 지금 키로 데이터가 온다 → 이 API 들은 이미 이용신청이 승인된 상태다.
- **기초자산 종목코드 없음.** `PROD_NM` 에서 " 선물" 을 떼 종목명으로 매핑해야 한다 — 사명 변경 이력에 주의(KRX 종목기본정보·창고 `security_ids` 의 이름 이력과 대조). `ISU_CD` 는 선물 상품 코드라 현물 코드가 아니다.
- 커버리지(2024-01-02): 유가 **158 상품**(그중 `ETF …` 접두 ETF 선물 6개 이상 섞임 — 걸러야 함), 코스닥 **39 상품** → 개별주식 약 190종목. 소스 스캔의 "200여 종목" 과 일치.
- 미결제 > 0 인 월물 행: 유가 266 · 코스닥 71(원월물 대부분 0 — 최근월·차근월만 쓰면 됨).
- 값(가격·괴리)은 보지 않았다.

### 2.4 백필 비용 추정

- 유가 2010-01-04~ 약 4,150 세션 + 코스닥 2015-08-03~ 약 2,750 세션 ≈ **6,900콜**, 순차 약 **3~4시간**(1.2~3.1초/콜).
- 원응답 그대로 저장 시 약 0.8~1MB/일 → 4GB 안팎. 월물(스프레드 제외)·미결제>0 또는 최근·차근월만 남기면 수십 MB.
- KRX Open API 일 호출 한도는 **미확인** — 한 번에 다 돌리지 말고 하루 수천 콜 이하로 끊을 것.

### 2.5 사용자가 할 일 (단계별)

이미 권한이 열려 있으므로 **새 신청은 필요 없다.** 확인만:

1. openapi.krx.co.kr 로그인 → **마이페이지 → API 이용현황(신청 내역)**.
2. "주식선물(유가) 일별매매정보"·"주식선물(코스닥) 일별매매정보" 의 **이용 기간 만료일** 확인. 신청 단위가 1/3/6/12개월이라 만료되면 401 이 난다 — 백필·정기 수집 전에 **12M 으로 연장**해 두기 권장.
3. (선택) 각 API 상세의 **"개발 명세서 다운로드"** 로 필드 정의 확인 — 특히 `SPOT_PRC` 가 기초자산 종가인지, 정산가 산정 기준. 받은 파일을 `docs/` 아래에 두면 매핑 작업 때 씀.
4. (선택) 주식옵션(N9) 도 볼 거면 같은 화면에서 "주식옵션(유가/코스닥) 일별매매정보" 이용 상태 확인.
5. 마이페이지에 **일 호출 한도**가 표시되면 알려 주기(현재 미확인).
