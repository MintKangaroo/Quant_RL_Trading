# RL 학습 진단 기록

`docs/design/rl-training.md §5` 가 정한 원인 배제 순서를 따라, **배제할 때마다 여기에
적는다.** 같은 원인을 두 번 조사하지 않기 위해서다.

---

## 2026-08-19 — 오라클 카나리(실제 환경) 불합격

M4-4-4. 합성 판(`tests/rl/test_oracle_canary.py`)은 통과하고, 실제 환경 판
(`tests/rl/test_real_env_canary.py`)은 **불합격**이다. 4-5(PPO 학습 루프)로 넘어가지
않는다.

### 무엇을 돌렸나

- 환경: `allocator/env.py` · 국장 · 2024-09-02~2026-07-03(거래일 444) · 16환경 병렬
- 학습 루프: 합성 판과 **같은** `modelops/canary_ppo.train_canary` (`env=` 로 실제
  환경만 갈아 끼웠다 — 루프가 두 벌이면 성적 차이를 환경 탓이라고 말할 수 없다)
- 오라클: 5거래일 뒤 실제 초과수익을 종목축 26번 칸에 주입(`FEATURE_ORACLE`)
- 200,000 스텝 · seed 0 · `OMP_NUM_THREADS=1` · 판당 14분

### 성적

| 판 | EV(마지막 5업데이트 중앙값) | 최고 EV | 오라클 기여도 순위 | 오라클/중앙값 |
|---|---|---|---|---|
| 오라클 켬 | **0.606** | 0.891 | **2위 / 28** | 3.9배 |
| 대조군(끔) | **0.903** | 0.965 | 27위 / 28 | 0.2배 |

§0 의 두 기준으로 읽으면:

- ① `EV > 0.5` — 켠 판은 0.606 으로 넘는다. **그런데 대조군이 0.903 이다.** 정답을
  빼도 더 잘 설명하므로, 이 환경에서 EV 는 배선을 판정하지 못한다
- ② 오라클 기여도 최상위 — **아니다.** 2위(1위 `Analyst0 신뢰도` 의 0.91배)

### 배선은 살아 있다 (중요)

불합격이지만 "정답이 정책에 닿지 않는다" 는 아니다:

- 오라클 칸의 정책 그래디언트 기여도가 켠 판 `1.13e-4`, 대조군 `1.68e-6` — **68배**다.
  꽂은 값이 정책 파라미터를 실제로 움직였다
- EV 가 0.13 → 0.6 으로 오른다(초기 구간 중앙값 0.135, 마지막 0.606). 상수 보상·죽은
  어드밴티지의 모양이 아니다
- 관측 주입 자체는 값까지 검증했다
  (`tests/allocator/test_env.py::test_오라클은_5일뒤_실제_초과수익이다` — 결정론적
  창고에서 손으로 계산한 값과 일치)

즉 **"코드가 끊어진 것" 이 아니라 "이 시험이 이 환경에서 판정력을 잃은 것"** 이다.
아래가 그 이유다.

### §5 원인 배제 — ①부터 순서대로

#### ① 리턴 정규화 누락 — **배제**

같은 예산(61,440 스텝)으로 정규화만 켜고 껐다.

| | EV | 오라클 순위 |
|---|---|---|
| `normalize_returns=True` | 0.482 | 2위 |
| `normalize_returns=False` | 0.408 | **1위** |

둘 다 EV 가 0 에 고착되지 않는다. §5 ① 이 겨냥한 증상(EV≈0)이 애초에 없다.
정규화는 켜져 있고(`canary_ppo` 의 `ReturnNormalizer`), 끄면 오히려 오라클이 1위로
올라온다 — 순위가 이 정도로 뒤집히는 것 자체가 **1·2위 차이가 잡음 안에 있다**는 뜻이다.

#### ② 액션 반영률 저하 — **경고선 위, 그러나 절반이 사라진다**

200k 판에서 반영률 0.39~0.49(중앙 0.45). §5 의 배선 경고선 30% 는 넘는다. 하지만
**RL 이 낸 목표비중의 절반 이상이 집행되지 않는다.** 원인은 셋이고 전부 의도된 코드다:

- `executor.sizing` 의 라운딩·최소주문금액(10만원)·거래대금 상한(ADV 3%)
- `env._decode` 가 종목 상한·현금 완충에서 깎은 몫을 **현금으로 보낸다**(다른 종목에
  재분배하지 않는다 — 불변식 7)
- 마스크된 슬롯의 비중도 현금이다

결과가 아래 ⑦ 의 "현금 59%" 다. 이것이 이번 불합격의 **주된 이유**로 보인다.

#### ③ 실현 비중 되먹임 누락 — **배제**

`tests/allocator/test_env.py::test_실현_비중이_다음_관측으로_되먹여진다` 통과. 다음
관측의 `FEATURE_REALIZED_WEIGHT` 가 체결 결과와 1e-6 안에서 일치한다.

#### ④ 상태 인코딩(순열 불변성) — **배제**

`tests/rl/test_canary_policy.py::test_종목_순서를_섞어도_같은_답이_나온다` 통과.
카나리 정책에는 위치 인코딩이 없다.

#### ⑤ 관측 정규화의 미래 누수 — **누수는 없다. 정규화 자체가 없다**

이 파이프라인에는 관측 정규화가 **한 줄도 없다.** 그래서 학습 구간 밖 통계가 새어
들어올 자리도 없다(누수 배제). 대신 **크기가 통제되지 않는다** — 실측:

| 칸 | 평균 | 표준편차 |
|---|---|---|
| 포트폴리오 6 · 환율 | 1,405.75 | 37.5 |
| 포트폴리오 18 · log자본 | 8.01 | 0.014 |
| 종목 24 · 보유경과일 | 14.96 | 11.8 |
| 종목 26 · 오라클 | 0.03 | 1.23 |
| 종목 2 · Analyst0 신뢰도 | 0.0011 | 0.0049 |
| 종목 20 · 최소스텝 | 0.0002 | 0.0003 |

환율 한 칸이 최소스텝보다 **일곱 자리** 크다. 정규화 없는 MLP 에서 이 칸들이 가치
헤드를 통째로 끌고 간다. 4-5 에서 관측 정규화를 넣기 전에는 어떤 피처 기여도 순위도
"그 피처가 중요하다" 가 아니라 "그 칸의 크기가 크다" 를 읽는 것일 수 있다.

#### ⑥ 가치 학습률 부족 — **배제**

`lr_value=9e-3`(정책의 3배, §4 비율). 대조군이 EV 0.96 까지 올라간다 — 가치함수는
배울 수 있는 것을 다 배웠다. 학습률이 모자란 모양이 아니다.

### §5 에 없는 원인 두 가지 (이번에 나온 것)

#### ⑦ 현금이 평균 59% 다 — 보상이 종목이 아니라 현금 드래그로 설명된다

`portfolio[2]`(KRW 현금비중) 평균 0.587. 보상은 초과수익이므로, 절반 넘게 현금인
포트폴리오의 보상은 근사적으로 **−0.59 × 벤치마크수익**이다. 벤치마크 1·5·20일
수익과 레짐은 이미 관측에 들어 있다(포트폴리오 15~17, 9~14).

→ **가치함수는 종목을 하나도 안 봐도 보상의 90% 를 설명할 수 있다.** 대조군 EV 0.903
이 그것이다. 이 구조에서는 오라클을 넣어도 EV 가 크게 오르지 않고(오히려 0.606 으로
낮다 — 정답을 쓰는 정책은 시장 성분에서 더 멀어져 예측이 어려워진다), §0 의 판정이
성립하지 않는다.

#### ⑧ 슬롯이 보유로 가득 찬다 — 새 후보가 매일 밀려난다

`_observe` 는 **보유를 먼저** 슬롯에 앉힌다(강제 청산을 막기 위한 옳은 선택이다).
그런데 실측으로 보유가 20스텝 만에 27~28종목이 되어 30칸을 거의 채우고, 그날 후보
5~11종목이 관측에서 통째로 밀려난다(`info["slots_dropped"]`). 오라클은 슬롯에 앉은
종목에만 실린다 — 즉 **정답이 닿는 자리가 며칠 지나면 "이미 산 것" 으로 좁아진다.**

### 곁가지로 드러난 것 — RL 캐시가 학습을 못 버텼다 (고침)

`allocator.env.cache_carry_sessions` 가 60 이었다. **에피소드 길이(250일)보다 짧다.**
RL 은 산 종목을 정책이 팔 때까지 들고 있고 보유가 슬롯을 먼저 차지하므로, 에피소드
중반부터 슬롯의 대부분이 "60세션보다 오래된 보유" 가 되어 매 스텝 창고로 되돌아갔다.

실측(16환경): 처음 48스텝 11ms/env-step → 그 다음 24스텝 **697ms/env-step**. 200k
스텝이면 39시간이다. 세션당 `market_stats` 한 번이 1.08초였다.

고침: 값을 250 으로 올리고(`config/rl_cache.yaml`, 정정본 발효 2026-08-19) 444세션을
다시 구웠다(30분 40초, 실패 0, 세션당 행 78 → 137). 같은 측정이 697ms → **5ms** 다.
값은 달라지지 않는다 — 캐시에 행을 더 남길 뿐이다(`build_session` 독스트링).

### 사람이 정해야 할 것 (4-5 전)

1. **§0 의 판정 기준을 이 환경에 맞게 다시 쓸 것인가.** EV 는 대조군이 0.90 인 이상
   판정력이 없다. 대안: 보상에서 시장 성분을 제거한 뒤의 EV, 또는 "오라클 기여도가
   중앙값의 N배" 같은 기여도 단독 기준
2. **현금 59% 를 먼저 고칠 것인가.** 반영률 0.45 와 같은 뿌리다. 고치면 EV 판정이
   되살아날 가능성이 높지만, 그것은 `executor.sizing` 의 제약을 건드리는 일이라
   실전 체결 가능성과 맞바꾸는 결정이다
3. **관측 정규화(⑤)를 4-5 의 첫 항목으로 넣을 것인가.** 넣지 않으면 이후 모든 피처
   기여도 해석이 크기 편향을 안고 간다
4. **죽은 칸 14개를 그대로 둘 것인가.** Analyst 슬롯 3쌍(6~8번 슬롯)·섹터 2칸·
   USD현금·US비중·레짐 4개는 설계상 비워 둔 자리지만, **한미금리차(포트폴리오 8)는
   200k 스텝 내내 0 이었다** — 이건 설계가 아니라 데이터 결손일 수 있다
