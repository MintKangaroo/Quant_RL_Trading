# 대시보드 명세

**스택**: Flask + ECharts (CDN). 별도 빌드 도구 없음.

참조 구현: `docs/design/fund-reference.html`
목업 데이터로 혼자 동작한다. 밀도·색·배치의 기준으로 삼되, 실제 구현은 API 연동으로 다시 만든다.

---

## 1. 설계 입장

"전문가 느낌"은 예쁜 차트가 아니라 세 가지다.

1. **정보 밀도** — 여백보다 정보. 한 화면에서 판단이 끝나야 한다
2. **추적 가능성** — 모든 숫자가 "왜 이 값인지"로 파고들어진다
3. **시점 명시** — 모든 숫자에 `as_of` 가 붙는다. 언제 기준인지 모르는 숫자는 쓸모없다

**이 대시보드는 수익률 대시보드가 아니라 리스크 예산 대시보드다.**
첫 질문은 "얼마 벌었나"가 아니라 "리스크 예산을 얼마나 쓰고 있나"여야 한다.

## 2. API 규약

```
GET /api/fund/summary?as_of=2024-03-05T15:30:00+09:00
```

- **모든 엔드포인트가 `as_of` 를 받는다. 예외 없음.**
  하나라도 빠지면 타임머신이 깨지고 나중에 전부 뜯어고쳐야 한다
- 응답에 `as_of` 를 되돌려준다 (화면 표시 + 캐시 키)
- `as_of` 가 없으면 라이브
- 밴드 경계(12/22/30)를 하드코딩하지 않는다. `store.config("reward")` 에서 읽는다.
  화면이 자기 숫자를 따로 들면 학습 설정과 어긋난다
- 폴링: 장중 5초 / 장외 1분
- Jinja는 뼈대만. 데이터는 전부 `/api/*` JSON

### Data Quality — 구현됨

```
uv run python tools/dashboard.py        # DASHBOARD_PORT (기본 6060)
```

| 엔드포인트 | 내용 |
|---|---|
| `GET /api/data-quality/summary` | KPI + 경고 판정 |
| `GET /api/data-quality/coverage` | 일별 종목 수, 기대 거래일 대비 |
| `GET /api/data-quality/missing` | 일별 close/volume 결측률 |
| `GET /api/data-quality/latency` | 단계별 p50/p90/p99 |
| `GET /api/data-quality/universe` | 상장 종목 수, 상장폐지 누적 |
| `GET /api/data-quality/failures` | 최근 수집 실패 |

전부 `as_of` / `lookback` 을 받는다. 응답 봉투는
`{as_of, live, lookback_days, thresholds, data}` 이며, `as_of` 를 되돌려주는 것이 규약이다.

규약은 `lattice/dashboard/api/common.py` 한 곳에만 있다. 집계는 Flask 를 모르는
`lattice/dashboard/services/data_quality.py` 가 하고, `tools/backfill.py --report` 가
**같은 함수**를 쓴다 — 같은 숫자를 두 곳에서 계산하면 언젠가 갈라진다.

`tests/invariants/test_dashboard_bans.py` 가 브라우저 저장소·차트 라이브러리 추가·
허용되지 않은 외부 출처를 정적으로 막고,
`tests/dashboard/test_data_quality_api.py::test_every_api_route_accepts_as_of` 가
URL map 을 훑어 불변식 9 를 강제한다 — 화면이 늘어나도 계속 강제된다.

## 4. Fund 화면 구성

```
┌─────────────────────────────────────────────┐
│ 브랜드 · 타임머신 슬라이더 · 시스템 상태     │
├─────────────────────────────────────────────┤
│ KPI 스트립 (8칸)                            │
├──────────────────────────┬──────────────────┤
│  순자산 vs 혼합 벤치마크   │  MDD 예산 게이지 │
│  (+ 초과수익 서브차트)     │  자본 배분        │
├──────────────────────────┤  오늘의 결정      │
│  언더워터 · 리스크 예산    │  Claude 리뷰 1줄  │
│                          │  에이전트 15점등   │
├──────────────────────────┴──────────────────┤
│  월별 초과수익 히트맵  │  핵심 지표 표        │
└─────────────────────────────────────────────┘
```

### KPI 스트립 (8칸)
순자산 · 일간 손익 · 누적 수익률 · **초과수익** · **정보비율(IR)** ·
현재 낙폭(예산 대비 %) · 자본 배분 · 원달러

### 언더워터 차트 ⭐ 시그니처
낙폭 곡선. 배경에 **12% / 22% / 30% 밴드를 색으로** 깐다.
보상 함수를 그대로 시각화한 것으로, 이 프로젝트에서 가장 중요한 그래프다.
벤치마크 낙폭은 점선으로 겹쳐 그린다.

### MDD 예산 게이지 ⭐ 시그니처
"8.3% / 30%" 수직 바. 12/22/30 구분선.

상태별 문구를 다르게 한다:
- 자유구간: `자유구간 · 낙폭 페널티 없음 · 여유 3.7%p`
- 페널티 구간: `페널티 구간 · 한계까지 12.4%p`
- 급증 구간: `급증 구간 · 신규매수 제한 · 한계까지 4.1%p`

**리스크를 안 쓰고 있는 것도 문제라는 걸 화면이 말해야 한다.**
"덜 잃고 덜 버는" 상태를 잡아내는 장치다.

### Claude 리뷰 (한 줄)
`headline` 만 표시. `severity` 에 따라 색. 클릭 시 전문 펼침.
전문은 `reviews` 테이블에서 조회한다.

### 오늘의 결정
후보 수 · 신규매수 · 청산 · **필터 거부(뉴스/SNS 분리)** ·
**목표 대비 실현 괴리** · **액션 반영률**

> 액션 반영률이 30% 미만이면 경고색. 선행 프로젝트가 룰 기반으로 전락한 것을
> 조기에 잡는 지표다.

### 핵심 지표 표 (전략 vs 벤치마크)
CAGR · 변동성 · 샤프 · 소르티노 · MDD · 승률 · **정보비율(IR)** · 트래킹에러 · 베타

### 타임머신 슬라이더
상단 슬라이더를 움직이면 모든 위젯이 그 시점 기준으로 재계산된다.
`as_of` 를 모든 API에 넘기는 것만으로 동작한다.

## 5. Decision Trace (화면 3)

종목 하나를 클릭하면 한 페이지에 전부 보인다.

```
KR:005930   매수 2026-08-07 09:31

[Signal]     Fundamental +0.7  Chart +0.4  Flow +0.8
             레이더 차트 + 각자의 evidence 펼치기

[Verdict]    News 통과 / SNS 통과
             (거부되었으면 category·reason·expires_at 표시)

[Selector] 종합 +0.63 → 후보 3위

[Allocator]     목표 비중 4.2%
             레짐: 상승 · 낙폭 여유 8.3%p · 최소 스텝 1.4%

[Executor]   실현 비중 4.0% (라운딩 −0.2%p)
             예상 71,200 → 체결 71,350 · 슬리피지 +0.21% (예측 +0.18%)
```

이것이 되면 사람이 "왜 샀지?"를 물을 필요가 없어진다.
Auditor도 같은 데이터를 그대로 사용한다.

## 6. 시각 스타일

```
배경     #0E1116      패널     #161A20      패널2  #1B2028
보더     #262C35      본문     #E6E9EE      보조   #8A93A0
흐림     #5A626D      경고     #F5A524
상승     #E5484D      하락     #3E7BFA      벤치마크 #6B7280
```

- **다크 기본.** 색은 손익과 경고에만 쓴다. 나머지는 무채색
- **상승 = 빨강(한국식)으로 통일.** 국장·미장을 같이 하므로 화면마다 다르면 사고가 난다
- 타이포: `IBM Plex Sans KR`(UI) + `IBM Plex Mono`(모든 숫자)
- 숫자는 `font-variant-numeric: tabular-nums` 필수
- 애니메이션 최소. 움직이는 대시보드는 아마추어처럼 보인다
- `prefers-reduced-motion` 존중, 키보드 포커스 가시화, 모바일까지 반응형

### 금지
- `localStorage` / `sessionStorage`
- 임계치 하드코딩
- 차트 라이브러리 추가 (ECharts 하나로 끝낸다)
