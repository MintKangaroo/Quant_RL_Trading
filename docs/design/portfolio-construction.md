# 포트폴리오 구성 — 섹터 방어 구조

스코어 비례 배분은 **리스크 구조를 완전히 무시한다.**
스코어 상위 20종목이 전부 반도체면 그건 분산이 아니라 한 종목 몰빵이다.

이 문서는 "무엇을 사는가"가 아니라 **"얼마나 사는가"** 를 리스크 구조에서 유도한다.

---

## 1. 방어 관계는 가정하지 말고 측정한다

"통신·유틸은 방어주"는 통념이지 사실이 아니다. 시기에 따라 바뀐다.
2022년 금리 급등기에는 유틸·리츠가 오히려 더 빠졌다.

**하방 베타로 직접 측정한다.**

```
시장이 하락한 날만 골라서:
  downside_beta(sector) = cov(r_sector, r_mkt | r_mkt < 0) / var(r_mkt | r_mkt < 0)
```

| downside_beta | 의미 |
|---|---|
| < 0.7 | 하락장에서 실제로 방어 |
| ≈ 1.0 | 시장과 같이 빠짐 |
| > 1.3 | 하락장에서 더 크게 빠짐 |

**상방 베타도 같이 잰다.** 이상적인 방어 섹터는 `하방 베타 낮고 상방 베타 높은` 비대칭 섹터다.
둘 다 낮으면 그냥 현금과 비슷하고, 그럴 바엔 현금을 드는 게 낫다.

> 상방/하방 베타를 **롤링 250일**로 계속 갱신한다. 고정 테이블로 박아두지 않는다.

---

## 2. 개별 종목 공분산을 직접 추정하지 않는다

30종목이면 상관계수가 435개다. 250일 표본으로 추정하면 **거의 전부 노이즈**다.
그대로 최적화기에 넣으면 추정 오차가 가장 큰 쌍에 극단적 비중이 몰린다
(mean-variance optimizer 의 고전적 실패).

**팩터 모델로 차원을 줄인다.**

```
r_i = α_i + Σ β_i,k · F_k + ε_i

F_k = 시장, 섹터(10개 내외), 시총, 밸류, 모멘텀, 변동성
```

이러면 추정 대상이 435개에서 **팩터 공분산 10~15개 + 종목별 노출**로 줄어든다.
훨씬 안정적이고, 무엇보다 **"이 섹터가 빠지면 저 섹터가 어떻게 되나"가 팩터 공분산에 직접 들어온다.**

여기에 **Ledoit-Wolf shrinkage** 를 걸어 추정 오차를 더 줄인다.

---

## 3. 비중 산출 — 리스크 기여 균등 + 스코어 틸트

순수 mean-variance 는 소액·소수 종목에서 불안정하다. 두 단계로 간다.

### 1단계 — 리스크 기여 기준선

```
RC_i = w_i · (Σw)_i / σ_p        (종목 i 의 포트폴리오 위험 기여도)
```

기준선은 **섹터별 리스크 기여를 균등하게** 만드는 비중이다.
금액이 아니라 **위험**을 균등 배분한다는 게 핵심 — 변동성 큰 반도체와
변동성 작은 통신에 같은 금액을 넣으면 위험은 반도체가 3배다.

### 2단계 — 스코어로 틸트

```
w_i ∝ RC기준선_i × exp(γ · combined_score_i)
```

`γ` 가 공격성이다. 0이면 순수 리스크 패리티, 크면 스코어 비례에 가까워진다.
**γ 는 진화 탐색 대상**으로 둔다 (Selector 유전자에 추가).

### 3단계 — 제약 투영

```
섹터 리스크 기여 상한   35%
단일 종목 리스크 기여   15%
하방 베타 가중평균      1.0 이하
현금 하한               레짐에 따라
```

## 4. 위기에는 상관이 1로 수렴한다 ⚠️

**이게 가장 중요한 현실이다.**

평시 상관 0.3이던 섹터들이 폭락장에서는 0.8~0.9로 붙는다.
"반도체가 빠지면 통신이 방어한다"는 관계는 **정작 필요한 순간에 사라진다.**

그래서:

- 공분산은 **하락 국면 표본에서 별도로 추정**해 두 개를 유지한다 (평시 / 위기)
- Regime Analyst 가 위기를 판정하면 **위기 공분산으로 전환**한다
- 위기 공분산에서는 섹터 분산의 방어 효과가 거의 0으로 계산되고,
  최적화기는 자연스럽게 **현금 비중을 올린다**

> 주식 안에서의 섹터 로테이션으로는 위기를 못 막는다.
> 진짜 방어는 **현금**이고, 그다음이 **통화**다.

### 원화 기준 평가의 자연 헤지

우리는 원화 기준으로 성과를 재기로 했다. 원화는 위기에 약해지는 통화이므로
폭락장에서 원달러가 오르고, **미장 포지션이 원화 기준으로 손실을 상쇄한다.**

이건 섹터 로테이션보다 강한 방어 장치다.
Allocator 상태값의 환율·환율변동성이 이 효과를 학습하는 경로다.

---

## 5. Allocator(RL)와의 충돌 처리 ⚠️

여기가 설계상 가장 위험한 지점이다.

RL 이 비중을 정하는데 그 위에 최적화기가 얹히면, **최적화기가 RL 출력을 덮어쓴다.**
그러면 액션 반영률이 떨어지고 — 그게 정확히 선행 프로젝트를 무너뜨린 실패 모드다.

**해결: 최적화기를 뒤가 아니라 앞에 둔다.**

```
❌ RL 비중 → 최적화기가 수정 → 주문
✅ 리스크 모델 → RL 상태값으로 제공 → RL 비중 → 최소 투영 → 주문
```

- Risk Analyst 가 팩터 노출, 하방 베타, 섹터 리스크 기여를 **상태값으로** 제공
- RL 은 제약을 보면서 스스로 만족하는 비중을 낸다
- Executor 는 **위반 시에만 최소 거리 투영**을 한다
- 투영 전후 차이를 **액션 반영률로 측정**하고, 30% 미만이면 경고

M3 룰 베이스라인에서는 §3 최적화기를 그대로 쓴다.
M4 에서 RL 이 이 베이스라인을 못 이기면 RL 을 쓸 이유가 없다는 판정 기준도 그대로다.

---

## 6. 소액 구간의 현실

최적화 결과가 4.2%인데 1주가 7%면 그 최적해는 존재하지 않는다.
종목 5~8개 구간에서는 정교한 최적화가 **정수 라운딩에 파괴된다.**

소액 구간에서 실효적인 것은 세 가지뿐이다:

1. **섹터 상한** (한 섹터 2종목 초과 금지 수준)
2. **하방 베타 가중평균 상한**
3. **현금 비중**

전체 최적화는 자본이 커진 뒤에 의미가 생긴다.
`log(자본규모)` 상태값이 이 전환을 RL 이 학습하는 경로다.

---

## 7. 검증

- 하방 베타가 낮게 측정된 섹터가 **실제 하락장 구간에서 덜 빠졌는지** 사후 확인
- 리스크 패리티 비중이 동일가중·스코어 비례 대비 MDD 를 낮췄는지
- 위기 공분산 전환이 실제 폭락 구간에서 현금 비중을 올렸는지
- 최적화기 투영이 스코어 상위 종목을 과도하게 깎지 않는지 (알파 손실)
- **팩터 모델의 설명력** — 잔차 분산 비율. 너무 높으면 팩터가 부족한 것
