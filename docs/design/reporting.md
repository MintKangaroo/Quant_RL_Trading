# 리포트와 Gmail 발송

대시보드는 **찾아가서 보는 것**, 메일은 **찾아오는 것**이다.
메일에는 "오늘 무슨 일이 있었는가"만 담는다.

---

## 0. 시황 브리핑 — 지금 실제로 나가는 한 통

아래 §1 의 마감 리포트는 **매매가 돌기 시작한 뒤의 것**이다. 2026-08 현재
`trades` 는 0행이고 실계좌 검증은 8/17~18 예정이다. 그 상태에서 §1 대로
① 오늘의 매매 · ② 학습 현황을 실으면 **빈 표가 나간다.** 빈 표는 "손실 0"
으로 읽힌다 — 없는 것을 0 으로 그리는 실패를 메일이 매일 반복하게 된다.

그래서 그때까지는 **시황만 담는 한 통**을 보낸다. 구현은
`quant_rl_trading/reporting/`, 실행은 `tools/send_briefing.py`.

```
[들어오지 않은 것]   창고에 빠진 세션·지수·환율을 이유와 함께
환율                 USD/KRW
국장 / 미장 각각      지수 · 변동성(별도) · 상승 종목 · 시장 폭 · 거시 · 주의 공시
```

성과·수익률·보유 섹션은 **없다.** 매매가 돌기 시작하면 이 위에 §1 의
①②③ 을 얹는다 — 시황 섹션을 걷어내는 것이 아니라 더한다.

### §1 과 갈리는 점 두 가지

**발송 시각.** §1 은 "국장 마감 후, 미장 결과는 다음 날, 새벽 발송 없음"
이다. 시황 브리핑은 **미장 마감 후** 하루 1통이고, 직전 국장 세션과 그날
미장 세션을 함께 담는다. 시황은 미장이 닫히기 전에는 절반만 아는 이야기라
국장 마감 시점에 보내면 매일 하루 낡은 미장을 싣게 된다. §1 이 새벽 발송을
금지한 이유(하루 여러 통 방지)는 **하루 1통** 을 지켜서 충족한다.

**시장마다 직전 세션이 다르다.** 2026-08-17(월)은 국장 휴장·미장 개장이다.
날짜 하나를 양쪽에 쓰면 그날 메일의 절반이 열리지도 않은 세션을 가리킨다.
시장별로 `market_hours.trading_days` 와 `publication_policy` 로 따로 구한다
(`reporting/sessions.py`).

### 크론 시각을 계절로 고정하지 않는다

미장 마감은 16:00 ET 고정이지만 KST 로는 서머타임에 따라 05:00/06:00 을
오간다. 크론을 KST 시각에 못 박으면 반년은 마감 전에 돈다.

- 권장: 크론을 `America/New_York` 로 걸고 **16:40 ET**
- 대안: KST 06:40 에 걸어도 된다 — 아직 공표 전이면 그 시장이 "세션 없음"
  으로 정직하게 나오고, 여름에는 두 시간 늦은 메일이 될 뿐이다

### 상승 종목에는 하한이 걸린다

거래대금·주가·거래대금 순위 셋. 값은 `config.reporting` 에 있다 (불변식 10).
하한이 없으면 이 섹션은 시황이 아니라 동전주 목록이 된다 — 1주 100원짜리가
30% 올라도 시장이 그쪽으로 움직인 것이 아니다. **적용한 하한을 본문에 적는다.**
숨긴 필터는 "왜 저 종목이 없냐" 에 답할 수 없고, 답할 수 없는 필터는 언젠가
아무도 믿지 않는다.

### 변동성 지수는 가격지수가 아니다

VIX·VXN·RVX 는 별도 표로 갈라 놓고 **손익 색을 쓰지 않는다.** VIX 상승은
수익이 아니라 공포다. 같은 표에서 초록·빨강을 칠하면 "VIX 가 올라서 좋다"
로 읽힌다. 명단은 `dashboard/services/market.py` 의 `VOLATILITY_INDICES`
하나뿐이다 — 두 벌로 두면 언젠가 갈린다.

## 1. 마감 리포트 — 하루 1통이 주력

발송: 국장 마감 후. 미장 결과는 다음 날 리포트에 포함된다.
새벽에 따로 보내지 않는다.

### 4개 섹션

```
[한 줄 요약]        Claude가 작성. 오늘 가장 중요한 한 가지

① 오늘의 매매
   체결 내역 (종목 · 수량 · 체결가 · 슬리피지)
   일간 손익, 초과수익, 낙폭 예산 사용률
   목표 대비 실현 비중 괴리
   액션 반영률          ← 30% 미만이면 경고 배지
   차단된 종목과 사유

② 학습 현황
   오늘 학습이 돌았는지, 몇 스텝
   explained_variance 추이 (7일 스파크라인)
   Analyst별 IC 60일 이동평균과 변화
   재학습 트리거 발동 여부
   ModelOps 판정 한 줄
   커리큘럼 단계 / 베이스라인 대비 IR

③ 뉴스 시황
   시장 전반 뉴스 3~5건
   보유·후보 종목 관련 뉴스
   News Analyst가 차단한 건과 카테고리

④ 주식 시황
   KOSPI · KOSDAQ · S&P500 · 나스닥 · 원달러
   섹터별 등락
   인기 주식 (거래대금 z-score 상위, 언급량 상위, 신고가)
   내일 예정 이벤트 (실적발표 · 배당락 · FOMC)
```

### 인기 주식은 매매 신호가 아니다

**참고 정보이지 후보가 아니다.** 리포트에 명시하고, 후보 리스트와 시각적으로 분리한다.

자동 편입되면 SNS 긍정 신호를 뒷문으로 들이는 셈이고, `agents.md` 에서 금지한 것이다.
각 인기 종목마다 **Quant_RL_Trading 후보 포함 여부**를 함께 표시하면
"왜 이 인기 종목을 안 샀나"가 자동으로 설명된다.

### 주간 리포트

금요일 마감 후 추가 발송. 주간 성과 귀속(종목/섹터/Analyst/환율),
Analyst IC 추이, 다음 주 KR/US 배분 변경 여부.

## 2. Gmail 발송 — LS_KR 세팅 재사용

LS_KR 에 Gmail 발송이 이미 구성되어 있다. **그대로 이식한다.**

이식 대상: SMTP 연결, 앱 비밀번호 로딩, 첨부 처리, 재시도 로직, 발송 로깅.

### 이식 시 반드시 고칠 것

- 자격증명은 `.env` 로 이동. 코드에 남아 있으면 제거하고 `.env.example` 에 자리만 남긴다
- Gmail 앱 비밀번호는 2단계 인증이 켜진 계정에서만 발급된다. 만료·회수 시 재발급 절차를 문서화
- 발송 한도가 있으므로 리포트는 하루 1~2통으로 제한한다. 종목별·이벤트별 발송 금지

### 실패 격리

**리포트는 비필수 경로다.**
생성 실패, Claude 호출 실패, SMTP 실패 어느 것도 Collector·Selector·Executor 에
전파되어서는 안 된다. 예외를 잡아 로깅하고 매매는 계속 진행한다.

## 3. 이메일 렌더링 — 현실적 제약

**이메일 클라이언트는 JavaScript를 실행하지 않는다. ECharts가 렌더되지 않는다.**

| 요소 | 방법 |
|---|---|
| 표·수치 | 인라인 CSS 테이블 (`<style>` 태그는 일부 클라이언트가 무시) |
| 차트 | 서버에서 PNG 렌더 → **첨부 후 cid 참조**. 외부 링크 이미지는 차단되는 경우가 많다 |
| 상세 | 대시보드 링크. `?as_of=...` 를 붙여 그 시점으로 바로 열리게 |

**라이트 배경을 쓴다.** 대시보드는 다크지만 메일에서 다크를 쓰면
클라이언트별 다크모드 반전으로 깨진다. 별개의 스타일이다.

차트는 NAV 곡선, 언더워터, explained_variance 추이 세 개까지.
나머지는 표와 스파크라인으로 처리한다.

Gmail은 본문 크기가 크면 잘라내므로(clipping) 본문을 간결하게 유지한다.

## 4. Claude API의 역할

**입력은 구조화 데이터만.** 원본 뉴스 본문을 그대로 넣지 않는다 —
프롬프트 인젝션 경로이고 비용도 통제 불가능해진다.

```json
{
  "headline": "반도체 3종목 동시 진입, 섹터 편중 8%p 상승",
  "severity": "warn",
  "sections": {
    "trading": "...", "learning": "...",
    "news": "...", "market": "..."
  }
}
```

- **숫자는 Claude가 만들지 않는다.** 모든 수치는 `store` 값을 템플릿에 꽂는다.
  Claude는 문장으로 엮기만 한다
- 매수·매도 추천 문구 금지. 사실과 근거만
- 결과는 `agent_cache` 에 저장. 리플레이 시 재호출 없음
- 실패 시 **템플릿 폴백** — Claude 없이 숫자 표만으로도 메일이 나간다
- 입력 상한: 후보 30 · 차단 10 · 인기 20 · 뉴스 20건

## 5. as_of 규율

```python
build_report(kind="close", as_of=clock.now())
```

- 모든 수치는 `store.get(as_of=...)` 경유
- 본문·입력 스냅샷·수신자·발송 시각을 `reports` 테이블에 저장
- 과거 날짜로 재생성했을 때 **그때 보낸 것과 동일해야 한다.**
  이것이 리포트의 결정론 테스트다
