# RL 학습 설계 (상세)

선행 프로젝트는 explained_variance ≈ 0 에서 벗어나지 못하고 9차 재정식화 끝에 폐기됐다.
이 문서의 목적은 알고리즘 선택이 아니라 **학습이 안 될 때 원인을 특정할 수 있는 순서**를 만드는 것이다.

## 0. 오라클 카나리 — 학습 전 필수 관문

**학습 코드를 신뢰하기 전에 배선이 살아 있는지 증명한다.**

상태값에 미래를 그대로 알려주는 가짜 피처를 심는다.

```python
# env config: oracle_leak = True (기본 False, 켜지면 로그에 크게 경고)
obs["per_asset"][:, ORACLE_IDX] = future_excess_return_5d   # 정답
```

| 결과 | 해석 | 다음 행동 |
|---|---|---|
| 정책이 이 피처를 이용해 큰 초과수익 | 배선 정상 | 실제 학습 시작 |
| 그래도 학습 안 됨 | **시장이 아니라 코드 문제** | §5 원인 목록으로 |

### 합격 기준 (2026-08-23 재개정) — 필요조건 셋

판정기는 `tools/verify_canary_gate.py`. 세 고리를 각각 재고 **셋 다 통과해야**
본 학습을 시작한다.

| | 무엇을 묻나 | 기준 | 실측(2026-08-23) |
|---|---|---|---|
| ① 환경 | 정답을 따르면 보상이 더 큰가 | 상위−하위 누적보상 ≥ 0.02 | **+0.171** ✓ |
| ② 용량 | 이 정책망이 그 매핑을 배울 수 있나 | 지도학습 200스텝에 정답 칸 비중 ≥ 0.5 | **0.966** ✓ |
| ③ 신용 | 보상이 advantage 까지 도달하나 | advantage↔정렬도 **t ≥ 2** | **t 3.31** ✓ |

셋은 **필요조건이지 충분조건이 아니다.** 통과는 "RL 이 돈을 번다" 가 아니라
**"학습을 시작할 자격이 있다"** 만 뜻한다. 실제로 배우는지는 카나리가 아니라
학습이 답하고, 그 판정은 milestones.md M4 의 "3회 실패 시 룰 베이스라인으로
회귀" 가 맡는다.

### ~~옛 기준: 오라클 기여도 ≥ 대조군 10배~~ — **무효다**

두 번 틀렸고, 두 번 다 "기준을 못 넘어서" 가 아니라 **판정 도구가 딴 것을
재고 있어서** 였다.

**첫째, 기여도가 엉뚱한 머리에서 왔다.** 2026-08-20 에 11.9배로 합격했는데
NAV 는 안 갈렸다. `attribution` 이 재는 `log_prob` 이 비중 항과 지연 항의
**합**이라 갈라서 재 보니:

    비중 항만  26위/28 · z -1.39      인과 탐침 -0.00002 ≈ 0
    지연 항만   3위/28 · z +0.42      인과 탐침 +0.00069  (35배)

정답의 그래디언트가 거의 전부 **지연 머리**로 흘렀다. 지연은 NAV 를 거의 안
바꾸므로 **통과해도 아무것도 보장하지 않았다.**

**둘째, 그 뒤 "정책이 눈에 띄게 집중해야 한다" 로 바꿔 쟀더니 그 요구가 그
예산에서 원리적으로 측정 불가능했다.** 이 기준으로 일곱 가설(κ·KL 조기종료·
엔트로피·정책망 구조·집행·보상·표본잡음)을 폐기했는데, 마지막에 남은 것은
가설이 아니라 산수였다:

    advantage ↔ 행동의 오라클 정렬도    r ≈ 0.043  (t 3.31 · 표본 6,048)
    r=0.043 으로 학습하는 데 필요한 그래디언트 스텝   ≈ 110,000
    그때까지 카나리가 준 예산                          768   ← 144배 부족
    본 학습(20M 스텝)의 예산                         97,600

**필요한 것의 0.7% 를 주고 "못 배운다" 고 판정해 온 것이다.** 신호가 약한
것(r=0.043)은 사실이지만 **살아는 있고**, 본 학습 예산은 필요치와 같은
자릿수다. 카나리가 학습의 대역을 서려 한 것이 애초의 잘못이었다 — 카나리는
**고리가 끊겼는지**만 보고, **배우는지**는 학습이 답해야 한다.

> 예산을 안 찍고 "안 배운다" 를 말하지 않는다. `diagnose_allocation.py` 가
> 시작할 때 그래디언트 스텝 수를 찍는 이유다.

~~explained_variance > 0.5~~ 는 **뺐다**. 실측에서 오라클을 끈 대조군의 EV(0.903)가
켠 판(0.606)보다 높았다 — 현금이 평균 59% 라 보상이 `-0.59 × 벤치마크` 에 지배되고,
그 시장 성분은 이미 포트폴리오 축의 벤치마크·레짐 칸에 있다. 즉 EV 는 오라클이 아니라
"이미 주어진 시장 칸을 읽을 줄 아느냐" 를 재고 있었다. **기준을 못 넘어서 낮춘 것이
아니라 판정 도구가 정답의 유무와 반대로 움직여서** 뺀 것이다. 현금 비중을 고치면
되돌린다. 근거와 실측은 `docs/rl-diagnosis.md`.

이 테스트는 `tests/rl/test_oracle_canary.py` 에 영구 보존하고,
학습 파이프라인을 고칠 때마다 재실행한다.
선행 프로젝트가 9차까지 간 이유는 "신호가 약한 것"과 "코드가 끊어진 것"을 구분할 수단이 없었기 때문이다.

## 1. 환경 인터페이스

Gymnasium 호환. `quant_rl_trading/allocator/env.py`

```python
class LatticeEnv(gym.Env):
    def reset(self, seed, options) -> (obs, info)
    def step(self, action) -> (obs, reward, terminated, truncated, info)
```

### 관측 (Dict space)

| 키 | 형태 | 내용 |
|---|---|---|
| `portfolio` | `(24,)` float32 | 낙폭 depth, 예산 잔여율, KRW현금, USD현금, KR/US배분, 환율(`log(환율/1000)`), 20일 환율변동성, 한미금리차, 레짐 one-hot(6), 벤치마크 수익 1/5/20일, log10(자본)/10, 최소스텝 중앙값, 남은 스텝 비율, 직전 회전율·반영률·유효후보비율 |
| `assets` | `(N_max, 28)` float32 | 종목 축 |
| `mask` | `(N_max,)` bool | 유효 후보 표시 (패딩 구분) |

`N_max = 30`. 후보가 적으면 패딩하고 `mask` 로 가린다.

**종목 축 28개 피처**: 종합점수, Analyst별 score×confidence(9쌍→18), **현재 실현 비중**,
최소 스텝, 청산 소요일수, 변동성, 베타, 보유 경과일(에피소드 길이로 나눔), 미실현 손익, 섹터 one-hot 축약.

**모든 칸은 O(1) 스케일이어야 한다.** 2026-08-27 까지 환율이 원값(1,478)으로, 보유 경과일이 일수(126)로,
자본이 log10(8.x)로 들어갔다. 1,478 하나가 포트폴리오 인코더 → 가치 헤드의 그래디언트를 1,000 대로 키웠고,
그것이 아래 §4 의 클리핑 문제와 겹쳐 정책을 굶겼다. 관측 칸을 새로 넣을 때는 이 표에 스케일도 같이 적는다.

### 액션 (Dict space)

| 키 | 형태 | 분포 |
|---|---|---|
| `weights` | `(N_max+1,)` | **Dirichlet** (마지막 슬롯 = 현금) |
| `delay` | `(N_max,)` | Categorical(4) — 0~3일 |
| `fx_alloc` | `(1,)` | Beta — 주간 스텝에서만 유효 |

**왜 Dirichlet인가**: softmax+Gaussian은 심플렉스 제약(합=1, ≥0)을 깨서 클리핑이 필요하고,
클리핑된 액션과 로그확률이 어긋나 정책 그래디언트가 편향된다. Dirichlet은 심플렉스 위에 직접 정의된다.

```python
concentration = softplus(logits) + 1e-3      # 수치 안정
concentration = concentration.clamp(max=1e3)  # 폭주 방지
# 마스킹된 슬롯은 concentration을 매우 작게 → 사실상 0 비중
```

### info 딕셔너리 (매 스텝 필수)

```python
{"realized_weights": ..., "target_weights": ...,
 "action_reflection_rate": ...,   # 핵심 진단
 "cost": ..., "drawdown": ..., "turnover": ...}
```

### 에피소드

- 길이 **250 거래일**. MDD는 경로 통계라 짧으면 30% 벽이 죽은 항이 된다
- 시작일은 학습 구간에서 무작위 샘플 (겹치는 윈도우)
- `terminated`: 낙폭 30% 초과 / `truncated`: 250일 도달

## 2. 신경망 구조

`quant_rl_trading/allocator/policy.py`

```
assets (N,28) ──> per-asset MLP (28→128) ──┐
                                            ├─> Transformer Encoder ×2
portfolio (24) ──> MLP (24→128) ─ CLS 토큰 ─┘   (d=128, heads=4, ff=256)
                                                 **위치 인코딩 없음**
                          │
        ┌─────────────────┼──────────────────┐
        ▼                 ▼                  ▼
  weights head      delay head          value head
  (128→1) per asset (128→4) per asset  (attention pool → MLP → 1)
  + cash logit
```

### 순열 불변성이 핵심

**위치 인코딩을 넣지 않는다.** 넣는 순간 "3번 슬롯"이라는 존재하지 않는 개념을 학습한다.
선행 프로젝트가 flatten을 썼다면 이것이 실패 원인 중 하나다.

테스트: 종목 순서를 무작위로 섞었을 때 정책 출력이 동일한지 (허용 오차 1e-5).

### 기타

- 포트폴리오 컨텍스트는 CLS 토큰으로 넣는다 (종목마다 concat하는 것보다 파라미터 효율적)
- 패딩 마스크를 attention과 헤드 양쪽에 적용
- 정책·가치 네트워크는 인코더를 **공유**하되 헤드만 분리 (데이터가 적어 공유가 유리)
- 직교 초기화, 정책 마지막 층 gain 0.01

## 3. 보상 구현

```
r_t = (r_port,t − r_bench,t) − w(d_t)·Δd_t − cost_t
```

`w(d)`: `d<12%` → 0 / `12~22%` → 1.5 / `22~30%` → 8.0 / `≥30%` → 종료 + 큰 음수

**모든 계수는 `store.config("reward")` 에서 읽는다. 하드코딩 금지.**

### 리턴 정규화 — explained_variance 0의 1순위 처방

일간 초과수익은 0.001 규모다. 정규화 없이는 가치함수가 이 크기를 학습하지 못한다.

```python
# 할인 리턴의 running std 로 보상을 나눈다 (VecNormalize 방식)
ret_rms.update(discounted_returns)
reward_normalized = reward / (sqrt(ret_rms.var) + 1e-8)
```

- **보상에 임의의 상수를 곱하지 않는다.** 낙폭 페널티와의 상대 비율이 깨진다
- 정규화 통계는 학습 중에만 갱신, 평가 시 고정
- 대안: PopArt (가치 헤드 출력 정규화). 둘 중 하나는 반드시 켠다

### 단위 테스트

- 낙폭 11.9% → 12.1% 이동 시 페널티 변화가 정확한지
- 신저점 미갱신일의 페널티가 0인지
- 30% 초과 시 `terminated=True` 인지
- 비용이 왕복 0.2~0.35%(국장) 범위로 차감되는지

## 4. 하이퍼파라미터 (출발점)

```yaml
algo: PPO
num_envs: 32
n_steps: 512                 # 배치 = 16,384
minibatch_size: 2048
n_epochs: 10
gamma: 0.997                 # 250일 에피소드 → 0.995 이상 필수
gae_lambda: 0.95
clip_range: 0.2
clip_range_vf: 0.2
ent_coef: 3e-3               # 선형 감쇠
vf_coef: 0.5
max_grad_norm: 0.5             # 정책·가치 손실을 **따로** 클리핑한다 — 아래 참조
lr_policy: 1e-4              # 선형 감쇠
lr_value: 3e-4               # 가치 쪽을 2~3배 높게
target_kl: 0.02              # 초과 시 조기 종료
total_timesteps: 20_000_000
normalize_returns: true
seeds: [0, 1, 2, 3, 4]
```

### 클리핑은 정책·가치를 따로 한다 (2026-08-27 실측)

한 손실(`policy + vf_coef·value − ent·entropy`)로 역전파한 뒤 전역 노름을 0.5 로 자르면,
**노름이 큰 쪽이 예산을 독식한다.** M4 2회차 340업데이트 체크포인트에서 잰 값:

    정책 손실 그래디언트   19.5   (1.2%)
    가치 손실 그래디언트 1659.3   (98.8%)  ← 값 헤드 1,015 · 포트폴리오 인코더 781
    합쳐서 0.5 로 자르면 정책 쪽 실효 학습률 = 1e-5 × 0.5/1659 ≈ 3e-9

로그의 approx KL 이 0.002(목표 0.02 의 1/10)에 머물고 정책 헤드 가중치 노름이 초기값
(0.05)에서 안 움직인 이유가 이것이다. 가치함수는 EV 0.3 까지 배웠고 정책은 아무것도
못 배웠다 — **보상이 평평한 것은 신호 부재가 아니라 정책이 굶은 것이었다.**

그래서 정책 손실(엔트로피 포함)과 가치 손실을 **따로 역전파해 각각 0.5 로 자른 뒤 더한다.**
공유 인코더는 두 방향을 다 받되 어느 쪽도 상대를 지우지 못한다. 로그의 gradient norm 은
정책 쪽 자르기 전 노름이다 — 학습이 되는지 보는 값은 그쪽이다. `lr_policy` 는 이 방식으로
다시 잰다(`allocator/train.py::train_config` 독스트링).

**γ를 낮추지 말 것.** 0.99면 유효 지평이 100스텝이라 250일 낙폭을 보지 못한다.

## 5. explained_variance ≈ 0 원인 점검 순서

증상이 나타나면 이 순서로 배제한다. 순서에 의미가 있다.

| # | 원인 | 확인 방법 |
|---|---|---|
| ① | **리턴 정규화 누락** | 정규화 on/off 비교. 가장 유력 |
| ② | **액션 반영률 저하** | `info["action_reflection_rate"]` 로깅. 30% 미만이면 배선 문제 |
| ③ | **실현 비중 되먹임 누락** | 다음 obs의 실현 비중이 체결 결과와 일치하는지 |
| ④ | **상태 인코딩** | 순열 불변성 테스트 실패 여부 |
| ⑤ | **관측 정규화의 미래 누수** | 통계가 학습 구간에서만 계산되는지 |
| ⑥ | **가치 학습률 부족** | lr_value 를 3배 올려 재시도 |

각 항목을 배제할 때마다 `docs/rl-diagnosis.md` 에 기록한다.
같은 원인을 두 번 조사하지 않기 위해서다.

## 7. 표본 부족 대응

5년 = 약 1,250거래일. 250일 에피소드면 겹치지 않는 것이 **5개뿐**이다.

## 8. 평가 프로토콜 — walk-forward

```
[학습 2년] [purge 5일] [검증 6개월] [embargo 5일] [테스트 6개월]
     └──────── 6개월씩 전진 ────────>
```

- 폴드는 최소 4개
- **하이퍼파라미터는 검증 폴드에서만** 튜닝한다. 테스트를 보는 순간 그건 테스트가 아니다
- 최종 보고는 전 폴드 테스트 구간을 이어붙인 것
- 모든 지표는 **3~5시드 중앙값** (단일 시드 성과는 보고하지 않는다)

## 9. 하이퍼파라미터 튜닝

### 중요도 순서

1. **리턴 정규화 방식** — 켜고 끄는 것만으로 EV가 갈린다
2. **lr_policy** (3e-5 ~ 3e-4, 로그)
3. **ent_coef** (1e-4 ~ 1e-2, 로그)
4. **gae_lambda** (0.9 ~ 0.99) — 금융은 노이즈가 커 낮은 쪽이 유리한 경우가 많다
5. **gamma** (0.995 ~ 0.999)
6. clip, epochs, minibatch — 기본값에서 벗어날 이유가 적다

### 방법

- Optuna + MedianPruner, 예산 **50~100 trial**
- 목적함수: **검증 폴드 IR의 3시드 중앙값**
- 시드 간 분산 > 하이퍼파라미터 간 차이 → 그 튜닝 결과는 노이즈. 채택 금지

### 절대 튜닝하지 않는 것

- 보상 함수 계수(12/22/30, w 값) — 투자철학이지 하이퍼파라미터가 아니다
- 비용 모델 — 실비다
- 에피소드 길이 — MDD 정의에 묶여 있다

## 10. 로깅 (전부 학습 탭에)

| 지표 | 정상 / 경고 |
|---|---|
| explained_variance | 0.1 이상. 0 근처 고착 = 실패 |
| approx KL | 0.01~0.02. 급등 = 학습률 과다 |

| **액션 반영률** | 30% 미만 경고 |
| 시드 간 분산 | 평균 대비 과대하면 결과 무의미 |
| policy churn | 일간 비중 교체율. 높으면 회전율 비용 폭증 |
| Dirichlet concentration 합 | 폭주 시 수치 불안정 신호 |

## 13. 승격

- OOS 백테스트 MDD 20% 이내

- **모의계좌 20거래일** — LS 모의투자 계좌(`data/_paper`)에 정책이 실제 주문을
  낸다. 룰 베이스라인은 shadow 장부(`data/_shadow`)에서 **같은 날 같은 후보로
  병주**한다. 둘의 차이가 곧 "정책이 룰보다 나은가" 다.
- 사람 승인 (실전 창고 `data/` 로의 승격)

승격 후에도 룰 베이스라인은 계속 돌린다. 언제든 되돌릴 수 있어야 한다.

### 2026-08-29 개정 — shadow 20거래일을 모의계좌로 바꾼 이유

원안은 "shadow 20거래일(주문 없이 결정만 기록) → 모의계좌" 였다. 모의계좌도
가짜 돈이고, 정책의 결정을 **실제 체결**까지 통과시켜야 액션 반영률·슬리피지·
최소주문금액이 만드는 실현 오차가 성적에 들어온다. shadow 는 그걸 못 본다.
그래서 OOS 판정(§0)을 통과하면 shadow 를 건너뛰고 모의계좌에 바로 끼운다.
룰과의 병주는 shadow 장부가 계속 맡는다.

**배선** (`allocator/live.py`, `session/daily.py`):

| 설정 | 뜻 |
|---|---|
| `allocator.rl.checkpoint` | 정책 체크포인트 경로. 비면 어디서도 정책을 쓰지 않는다 |
| `allocator.rl.modes` | 정책이 결정하는 장부 모드(`store/mode.py`). 기본 `["paper"]` — shadow·실전은 룰 |

- 관측은 `LatticeEnv.observe_live` — **학습이 쓴 피처 코드 그대로**, 장부만
  실제 장부(`accounting.ledger`)다. 라이브라서 다른 세 칸(남은 스텝 비율은
  0.5 고정, 보유 경과일은 창 시작에서 자름, 직전 회전율·반영률은 창고에서)은
  그 함수 독스트링에 적었다.
- 행동은 평균(Dirichlet α/Σα, 지연은 argmax). `tools/evaluate_policy.py` 와 같다.
- **노출 제어(`selector/exposure.py`)를 거치지 않는다.** 정책은 현금을 액션 한
  칸으로 직접 정하며 학습 환경에 노출 배수가 없었다. 위에 배수를 곱하면
  정책의 현금 결정을 룰이 덮어쓴다 — 선행 프로젝트가 룰로 전락한 길이다.
  이벤트 로그에는 `exposure` 가 `rl:policy_cash` 로 남는다. 킬스위치는 집행기에
  그대로 있다.
- 진입 지연 > 0 인 매수는 "오늘은 안 산다" — 목표를 오늘 실현 비중에 둔다.
  내일 정책이 다시 본다.
- 사이징·집행·실현 비중 기록·액션 반영률은 룰과 **같은 길**이다. 이벤트
  `allocate` 의 driver 가 `rl` 이고 payload 에 `policy`(슬롯·지연·현금·
  체크포인트·업데이트 번호)가 붙는다.

# 과적합 점검 — 학습이 끝나면 반드시 한다 (2026-08-23 등록)

## 먼저: 구조가 이미 위험하다

학습을 띄운 뒤 산수를 해 봤다.

    학습 구간        362거래일 (2025-01-02 ~ 2026-06-30)
    에피소드 길이     250일
    서로 다른 시작점  약 112개
    총 에피소드      80,000개  (20M 스텝 ÷ 250)
    → 같은 시작점을 평균 **714번** 반복해서 본다

**정책은 같은 18개월치 시장 역사를 714번 본다.** 그러면 "어떤 상황에서
무엇을 사는가" 라는 규칙을 배우지 않고 **"2025-03-14 에는 이 종목을 사라"**
를 외워도 손실이 줄어든다. 에피소드가 250일인데 창이 362일이라 에피소드끼리
거의 겹치는 것도 같은 방향으로 작용한다.

이건 학습이 끝난 뒤에 발견할 일이 아니라 **지금 알고 있어야 할 전제**다.
EV 가 올라가는 것(0.72)이 일반화의 증거가 아닐 수 있다.

## 무엇을 잴 것인가

**① OOS 성적 (핵심).** 학습이 한 번도 안 본 구간에서 돌린다.

    2026-07-01 ~ 2026-08-22 = 36거래일

훈련 구간 성적과 나란히 놓는다. **격차가 크면 외운 것이다.**

**② 룰 베이스라인 대비 (M4 완료 기준).** 같은 OOS 구간에서 score 베이스라인과
견준다. RL 이 훈련 구간에서만 이기면 그것이 과적합의 정의다.

**③ 시드 분산.** 다른 시드로 짧게 재학습해 성적이 크게 흔들리는지 본다.
흔들리면 배운 것이 아니라 그 시드가 우연히 맞은 것이다.

**④ 행동 집중도.** 정책이 특정 종목·특정 날짜에 쏠리는지 본다. 외운 정책은
상황이 아니라 **날짜**에 반응한다.

**⑤ 날짜 뒤섞기 대조군.** 관측은 그대로 두고 에피소드 시작점만 바꿔 돌린다.
성적이 무너지면 상황이 아니라 순서를 외운 것이다.

## 미리 적어 두는 한계 — 36일로는 많은 것을 못 가른다

카나리에서 배운 대로 **표본이 판정력을 정한다.** 36거래일은 파국적 과적합
(OOS 에서 완전히 무너지는 것)은 잡지만, 미묘한 차이는 못 가른다.
"OOS 가 조금 나빴다" 를 근거로 결론을 내리지 않는다 — **필요 표본을 같이
계산해서 적는다.**

## 그리고 이 결과로 무엇을 할지 미리 정해 둔다

- **OOS 가 무너지면**: 에피소드 반복이 원인일 가능성이 크다. 고칠 방향은
  학습 구간을 넓히거나(과거 데이터 백필) 에피소드를 짧게 해 시작점을 늘리는
  것이지, **하이퍼파라미터를 흔드는 것이 아니다.**
- **OOS 가 버티면**: 그때 모의계좌 20거래일로 넘어간다(M4 완료 기준, §13 2026-08-29 개정 — shadow 단계는 뺐다).
- 어느 쪽이든 **3회 실패 시 룰 베이스라인 회귀** 규칙은 그대로다.

    OOS(안 본 것)·정책 vs 균등가중     -0.00058   ← 우위가 없다

## 2회차 사전 점검표 — 전부 켜지기 전에 띄우지 않는다 (2026-08-25)

1회차의 실패 다섯이 전부 **띄우기 전에 확인 안 한 것**이었다(예산 산수·평가
도구·판정 기준). 판정기는 `tools/verify_round2_ready.py` — verify_m3 규약대로
PASS·FAIL·미측정 셋이고, **체크박스를 손으로 켜지 않는다.**

### A. 신호 — 이번 판이 1회차와 달라야 하는 이유

| # | 항목 | 기준 |
|---|---|---|
| A1 | 카나리 게이트 3종 | `verify_canary_gate.py` 전부 PASS (환경·용량·신용) |
| A2 | **신호 세기 r 재측정** | 보상 분리(§8)·한계기여 가중이 들어간 뒤 잰 r 이 1회차(0.043)보다 크고, **필요 스텝(≈200/r²) ≤ 학습 예산** |
| A3 | 보상 분해 배선 | selection+exposure = excess (기계 정밀도) · info 에 실림 |

**A2 가 관문의 심장이다.** r 이 안 올랐는데 띄우면 38시간을 또 버린다 —
그대로 1회차의 재방송이 된다.

### B. 학습 구조 — 외울 수 없어야 한다

| # | 항목 | 기준 |
|---|---|---|
| B1 | 에피소드 반복 산수 | 같은 시작점 반복 ≤ **150회** (1회차 714회 · 백필 후 예상 85회) |

## 2회차 판정 (2026-08-29) — 실패 · 과적합, 원인은 현금 타이밍

실행 `m4-round2-s0-c1-r6-c3` (분리 클리핑 · 관측 스케일 수정 · C1 · 시드 0 · 1220업데이트,
OOM 재개 2회). 학습 구간 보상 −0.011 → +0.016, 반영률 0.67, 현금 2.5%, 과적합 전조 없음.

**① OOS 판정** (`tools/evaluate_policy.py --envs 16 --save` → `rl_evaluations`)

| 구간 | 정책 | 균등가중 | 차이 | 정책 현금 | 비용/일 (정책/균등) |
|---|---|---|---|---|---|
| 학습(본 것) | −0.00410 | −0.00505 | **+0.00095** | 19.5% | 0.00018 / 0.00006 |
| OOS(안 본 것) | +0.00462 | +0.00631 | **−0.00170** | 18.4% | 0.00018 / 0.00006 |

학습 구간에서만 이긴다 — 과적합. 4환경(−0.00186)·16환경(−0.00170) 두 자 모두 같은 판정.
r5 의 −0.00058 보다 나빠졌다. **모의계좌 투입 조건 미충족 — 켜지 않았다** (§13 배선은 준비됨).

**분해.** 비용 격차는 0.00012/일로 전체 격차의 7%. 나머지는 **현금**이다 — 20일 창에서
정책은 현금 18~19%, 균등가중은 7%. OOS 는 오르는 장(균등 +0.63%/일)이라 현금이 그대로
손해였다. 학습 로그의 "현금 2.5%" 는 250일 에피소드 후반 값이고, **현금에서 출발하는
첫 20일에는 정책이 느리게 들어간다**(진입 지연 액션 + 반영률 0.86).

**이 판정의 한계 두 가지** (결론의 세기를 정한다)
- 평가 자가 거칠다: OOS 36거래일, 20일 에피소드는 "진입 속도" 를 성적으로 크게 잰다.
  그래서 "확실히 나쁘다" 가 아니라 "**통과했다고 말할 수 없다**" 다.
- 천장이 낮다: 후보 상위 24 동일가중 ≈ 시장(2026-08-27 발견). 후보에 알파가 없으면
  정책이 배울 것은 "무엇을" 이 아니라 "언제·얼마나" 뿐이고, 그건 구간에 묶이는 지식이다.

**회고 — 다음 판 전에 바꿀 것** (같은 설정으로 한 번 더 돌리지 않는다)
1. **평가 자 먼저.** 에피소드를 현금이 아니라 보유 상태에서 출발시키고(진입 속도 제거),
   학습 구간 안에 워크포워드 폴드를 두어 §13 "검증 폴드 3시드 중앙값" 을 실제로 잰다.
2. **외우기 억제.** 에피소드 시작점 반복(평균 714회) 줄이기 · 후반 학습률 감쇠(후반 KL 상한
   조기종료 66%) · C1→C2 로 비용을 넣어 회전 습관 교정 · 진입 지연 액션 제거 검토(라이브에
   대응물이 없고 OOS 에서 해만 됐다).
3. **재료.** §7 risk_parity 비교와 노출 제어 기여 분해로 룰 쪽 천장부터 올린다. 3회차 학습은
   이 결과를 보고 결정한다 — **시도 상한 5회(2026-08-29 사용자 결정, 원안 3회) 중 3회 남았다.**
4. 운영: 학습 프로세스 메모리 2.6→5GB 성장(OOM 3회) 원인 추적 · 학습기의 지연 선택지 3 하드코딩
   vs 설정 4 불일치(`load_policy` 는 체크포인트를 따른다).

**시드 분산(③)은 못 쟀다** — 시드 1개. 학습 탭 "운이었나 실력이었나" 가 그렇게 말한다.

## 3회차 설계 (2026-08-29 등록) — 외울 수 있는 자유도를 정책에서 뺀다

### 근거 (같은 날 실측, `logs/evaluate-early-ckpts.log`)

| r6 체크포인트 | 학습 우위 | OOS 우위 | OOS 현금 |
|---|---|---|---|
| 업데이트 220 | −0.00000 | −0.00012 | 9.2% |
| 업데이트 1080 | +0.00095 | −0.00179 | 17.9% |
| 업데이트 1220 | +0.00095 | −0.00170 | 18.4% |

220 에서는 균등가중과 같았고, 그 뒤에 배운 것은 **현금 타이밍뿐**이며 그것이 통째로 외운
것이었다. 조기 종료로 고를 "좋은 중간 시점" 이 없었다 — 그래서 학습률·정규화만 만지는
것으로는 부족하고, **배울 수 있는 것 자체를 바꾼다.**

### 바꾸는 것

| # | 변경 | 코드 | 이유 |
|---|---|---|---|
| 1 | **현금은 액션이 아니다** `cash_action=fixed` | `env._decode` · `train_rl --cash-action fixed` | 투자 비중 = 1 − cash_buffer 고정. 정책은 후보 사이 배분만. 노출("얼마나")은 룰(`selector/exposure`, 변동성 압축은 OOS 증거 있음) |
| 2 | **보유 상태 출발** `warm_start` | `env._warm_start` · `--warm-start` | 첫날 후보 균등가중을 실제 수수료로 사서 시작. 짧은 창에서 "진입 속도" 가 성적을 지배하지 않게. 학습·평가 둘 다 |
| 3 | **검증 폴드로 체크포인트 선택** | `--keep-checkpoints` + `tools/select_checkpoint.py` | 학습 2023-01-02~2025-12-31, 검증 2026-01-02~06-30(120일). 검증 우위 최대 체크포인트를 쓴다. 마지막 정책은 제일 많이 외운 정책 |
| 4 | 학습률 코사인 감쇠 | `--lr-decay cosine` | 후반 KL 상한 조기종료 66%(2회차) |
| 5 | C2 — 비용 포함 | `--c1` 없이 | 회전 습관 교정 |
| 6 | 시작점 반복 ≤ 150 | `--timesteps 15000000` | 학습 구간 ~735세션, 250일 에피소드 → 시작점 485 · 반복 ≈124 |
| 7 | 지연 액션 | 이미 고정(train.DELAY_FIXED). 라이브도 0 으로(live.py) | 안 배운 머리의 argmax 는 잡음이었다 |

체크포인트가 `env_overrides`(cash_action·warm_start)를 들고 다닌다 — 평가(`evaluate_policy`)와
라이브(`allocator/live.py`)가 **학습이 쓴 설계 그대로** 결정을 푼다. fixed 정책은 세션에서
룰 노출 배수를 그대로 탄다(free 정책만 우회).

### 파일럿 게이트 — 본 학습 전에 (미리 고정)

새 설정으로 **150업데이트** 안팎을 `--keep-checkpoints` 로 돌리고 `select_checkpoint` 로
20업데이트마다 학습 폴드 vs 검증 폴드 우위를 나란히 본다.

    통과: 마지막 3개 체크포인트의 검증 우위 > 0 이고, (학습 우위 − 검증 우위) 가 첫
          체크포인트보다 커지기만 하지 않을 것
    실패: 검증 우위가 0 근처(배울 알파가 없다 — 재료 문제) 또는 격차가 벌어지기만 함
          → 본 학습을 띄우지 않는다. 시도 1회를 아낀다.

### 본 학습 (파일럿 통과 시)

    train_rl --curriculum C2 --cash-action fixed --warm-start --keep-checkpoints
             --lr-decay cosine --timesteps 15000000 --train-start 2023-01-02
             --train-end 2025-12-31 --threads 6 --checkpoint-every 20

완주 후 `select_checkpoint` 로 검증 최적 체크포인트 → `evaluate_policy --save` 로 홀드아웃
(2026-07-01~08-22) 판정 → 통과 시 `promote_policy` 로 모의계좌. 시도 상한 5회 중 3회째.

### 이 설계가 못 고치는 것

후보(상위 24)에 알파가 없으면 배분을 아무리 잘 배워도 균등가중과 같다. 파일럿의 검증
우위가 0 근처면 그 신호다 — RL 이 아니라 Analyst 재료(사전등록 시행 A·B)와 §7 의 문제.
