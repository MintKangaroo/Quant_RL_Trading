# 에이전트 명세

15개 에이전트는 세 층으로 나뉜다. 성격이 서로 다르다.

```
Collector 2      수집만. 점수를 내지 않는다
Analyst 8     점수 또는 판정을 낸다
결정층 5      Selector · Allocator · Executor · Auditor · ModelOps
```

---

## 1. Signal 스키마

```json
{
  "signal_id": "uuid",
  "session_id": "2026-08-07-KR",
  "analyst": "chart",
  "analyst_version": "chart-v1.3.0",
  "entity_id": "KR:005930",
  "as_of": "2026-08-07T08:35:00+09:00",
  "score": 0.62,
  "confidence": 0.81,
  "horizon_days": 5,
  "features_hash": "sha256:...",
  "evidence": [{"key": "rsi_14", "value": 38.2, "note": "과매도 이탈"}],
  "latency_ms": 143
}
```

### score의 정의 (반드시 하나로 통일)

```
score = tanh( 예측 초과수익의 횡단면 z-score / 2 )
```

> horizon_days 뒤, **같은 시장 종목들 대비** 얼마나 더 오를 것인가

정의가 통일되지 않으면 Selector이 점수를 합칠 수 없다.

### confidence

에이전트가 스스로 매기지 않는다. **최근 60일 롤링 IC로 자동 계산**한다.
스스로 매기게 하면 과신한다.

### horizon 통일

타깃은 **5일**로 통일한다. 재무 Analyst처럼 느린 신호도 5일 예측에 기여하되
IC가 낮게 나오는 것이 정상이다. 5일에서 IC 0.03을 못 넘으면 기준을 낮추지 말고
**horizon 20일 버전을 별도 모델**로 추가한다.

## 2. Analyst — 점수를 내는 3명

### Chart

- **모델**: LightGBM 회귀 · **갱신**: 5분
- 추세(MA 이격도, 정배열, ADX) / 모멘텀(수익률, RSI, MACD) /
  변동성(ATR, 실현변동성, 볼린저) / 위치(52주 고저)
- **거래량 축은 여기 없다.** 2026-08-21 에 `volume` 으로 나갔다 (아래)
- ⚠️ 기술지표는 상호 상관이 0.9를 넘는다. **30개 이하로 자르고** SHAP으로 정리
- ⚠️ 모든 피처는 **같은 시장 내 횡단면 z-score**. 국장과 미장을 섞지 않는다

### Volume (거래량) — chart 에서 떼어냈다 (2026-08-21)

- **모델**: 없음. 피처 하나 — 5일 평균 거래량 / 60일 평균 − 1
- 국장 300세션 실측에서 chart 6피처 중 **유일하게 유의했다**
  (IC +0.0140 · t +2.28, `signal-combination.md` §6). 나머지 다섯이 가중치의
  90% 를 쥐고 전부 음수라, 한 점수에 섞여 있는 한 이 축은 게이트를 따로
  통과할 수 없었다
- ⚠️ **관찰 모드다.** +0.0140 은 0.03 에 못 미친다. 갈라낸 목적은 통과가
  아니라 따로 판정받는 것이다
- ⚠️ 정의를 손대지 않고 옮겼다. 창을 바꾸면 위 측정과 이어지지 않는다

### Flow (수급) — `flow_kr` / `flow_us` 두 개의 별도 모델

국장과 미장은 데이터 자체가 달라 같은 모델을 쓸 수 없다.

**국장** (풍부 — 알파의 주요 원천)
투자자별 순매수(외인/기관/개인/연기금/사모/투신/보험), 시총 대비 정규화, 1/5/20일 누적,
외인 지분율 변화, 공매도 비중, 대차잔고 증감, 신용잔고율, 주체 일치도

**미장** (희박 — 투자자별 수급 공시가 없다)
short interest(격주), 13F(분기·지연), ETF 자금흐름, 옵션 put/call·미결제약정

IC를 따로 측정한다. 미장이 0.03을 못 넘으면 미장에서만 가중치 0으로 두고 국장에서는 사용한다.

⚠️ 장중 잠정치와 마감 확정치는 `observed_at` 이 다르다. 별도 행으로 저장.

**커버리지 게이트는 유니버스가 아니라 창의 중앙값 대비로 잡는다.**
`flows` 는 국장 전 종목을 담지 않는다 — 2,800종목 중 991종목만 들어온다.
유니버스 대비로 재면 **정상인 날도 전부 미달**이라 Analyst 가 영원히 침묵하고,
그건 "수급이 안 먹혔다" 가 아니라 "잰 적이 없다" 다. 잡아야 할 것은 낮은
커버리지가 아니라 커버리지의 **붕괴**다.

**수급이 관측된 종목만 의견 대상이다.** 나머지를 z=0 으로 채우면 1,800종목이
한 덩어리 동점이 되고, 순위상관인 IC 가 그 동점에 눌려 0 쪽으로 끌려간다.
의견이 없는 것과 중립 의견은 다르다.

⚠️ **미장은 입력이 0건이라 항상 빈 신호를 낸다 — 그게 맞는 동작이다.**
명단에서 빼면 아무도 "왜 없지" 를 묻지 않게 되므로 자리를 남긴다.

### Fundamental

밸류(PER/PBR/PSR/EV·EBITDA/FCF yield) / 퀄리티(ROE, ROIC, 영업이익률, 부채비율, 발생액) /
성장(매출·영업이익 YoY·QoQ, 3년 CAGR) / 서프라이즈(컨센서스 괴리, **추정치 리비전**)

- ⚠️ 밸류 지표는 절대값이 무의미하다. **섹터 내 백분위**로 변환
- 💡 추정치 리비전은 가장 강한 팩터 중 하나다. 컨센서스 데이터를 구할 수 있으면 반드시 포함

## 3. Analyst — 필터 2명 (점수를 내지 않는다)

과거 뉴스·SNS 데이터를 확보할 수 없으므로 **RL 상태값에 넣지 않는다.**
검증할 수 없는 신호에 위험한 권한을 주지 않는다.

### Verdict 스키마

```json
{
  "entity_id": "KR:005930",
  "verdict": "block",
  "severity": 0.8,
  "category": "dilution",
  "reason": "...",
  "expires_at": "2026-08-12T09:00:00+09:00"
}
```

### News

**차단**: 회계부정·감사의견거절 / 횡령·배임 / 상폐 실질심사 / 거래정지 /
대규모 소송 패소 / 리콜 / 유상증자·CB 발행(희석) / 최대주주 매도 / 실적 쇼크

**차단하지 않음**: 단순 주가 하락 기사 / 목표가 하향 / 일반적 부정 논조

전부 차단하면 살 종목이 남지 않는다. **사실 기반의 구조적 악재만** 차단한다.

- `expires_at` 필수 (기본 3~5거래일). 영구 차단 금지
- 차단한 종목의 이후 수익률을 추적해 성적표를 만든다

**2단계 판정 — 키워드만으로는 못 쓴다.** 실측한 오탐이다(히트 4건, 4건 전부):

| 제목 | 왜 오탐인가 |
|---|---|
| "SK하이닉스, 日키오시아 최대주주 등극" | 최대주주가 **된** 호재인데 `INSIDER_SELL` 로 잡힘 |
| "충칭공장 지분 매각 검토" | 자산 매각이지 최대주주 매도가 아님 |
| 삼성전자로 검색한 기사에 SK하이닉스 악재 | **종목 귀속이 틀림** |

방향(호재/악재)·주체(한 일인지 당한 일인지)·귀속(그 종목 이야기가 맞는지)은
문자열 매칭으로 판별할 수 없다.

2단계는 **1단계 히트를 기각만 한다.** 새로 찾지 않으므로 오작동해도 최악이
"덜 막는다" 이고, 이 필터의 비대칭(매수 금지만, 매도 권한 없음)과 방향이 같다.
**이 출력은 보상 함수에 들어가지 않는다** (불변식 8).

**차단 상한은 올림이되 전부는 못 막는다.** 내림으로 두면 후보 3종목에서
`int(3 × 0.3) = 0` 이 되어 필터가 구조적으로 무력해진다. 상한의 목적은 비율
자체가 아니라 "살 종목이 남아 있을 것" 이므로, 마지막 한 종목은 언제나
살아남는다.

### SNS

**긍정 신호는 사용하지 않는다.** 언급량 폭증은 대부분 이미 오른 뒤이거나 작전이다.

유일한 용도는 **펌핑 탐지**:
언급량 z-score 급등 + 신규·저품질 계정 비율 급증 + 다채널 동시 게시 + 반박 없는 일방적 찬양

### 공통 제약

- **매수 금지만 가능. 매도 권한 없음.**
  오작동해도 기회를 놓칠 뿐 손실이 확정되지 않는다
- 하루 거부 가능 종목 수 상한: 후보의 30%
- 거부 사유 전부 로깅

| 에이전트 | 방식 | 내용 |

| **Regime** | HMM 또는 룰 | 상태 4~6개(강세/약세/횡보/고변동/위기). 입력: 지수 수익·변동성(VKOSPI/VIX), 금리, 신용스프레드, **시장 폭** |

## 5. Selector — 후보 선정

```
1. 유니버스 필터 (거래대금 하한 / 관리종목·거래정지 제외 /
                  상장 6개월 경과 / 1주 가격 < 자본의 15%)

2. Signal 취합 — 죽은 Analyst는 중립 0 처리
   score = Σ(wᵢ · scoreᵢ · confᵢ) / Σ(wᵢ · confᵢ)

3. News·SNS 거부 종목 제외 (거부 상한 30%)

4. 리스크 상관 페널티 — 이미 뽑힌 종목과 60일 상관 0.7 초과 시 감점

5. 상위 N개 → 후보 리스트
```

3번을 4번보다 먼저 둔다. 상관 계산은 비싸고, 거부된 종목까지 계산할 필요가 없다.

`wᵢ`(Analyst 가중치)는 **진화 알고리즘으로 탐색**한다. 여기가 실제 알파의 원천이다.

## 6. Allocator — RL 제어기

### 상태값 — 포트폴리오 축

```
현재 낙폭 depth, MDD 예산 잔여율
현금비중 (KRW / USD 분리)
KR/US 배분
원달러 환율, 20일 환율변동성, 한미 금리차
레짐 one-hot
벤치마크 수익 (1/5/20일)
log(자본규모)
```

### 상태값 — 종목 축 (후보 N개)

```
종합점수, Analyst별 score·confidence
현재 실현 비중          ← 목표가 아니라 실제 체결된 값
최소 스텝 (1주 = 몇 %)
청산 소요일수
변동성, 베타
보유 경과일, 미실현 손익
```

⚠️ 종목 순서가 바뀌어도 같은 답이 나와야 한다. **set encoder(attention)** 를 쓴다.
단순 flatten하면 "3번 슬롯"이라는 존재하지 않는 개념을 학습한다.

💡 `log(자본규모)` 와 `최소 스텝` 이 소액·거액 정책 통합의 핵심이다.

### 액션

```
[일간]  종목별 목표비중 — softmax(N+1), 현금 포함
        진입 지연 0~3일 — discrete
[주간]  KR/US 배분 — 스칼라 1개
```

**종목 선택은 하지 않는다.** 선택까지 RL에 맡기면 차원이 폭발하고 학습이 붕괴한다.

## 7. Executor — 실행 순서가 곧 안전

```
1. 킬스위치 latch 확인          ← 걸려 있으면 여기서 종료
2. 데이터 품질 게이트
3. 시장 서킷 브레이커 (KOSPI/KOSDAQ 분리)
4. defer 게이트 (개장 후 30분 신규매수 보류)
5. 목표비중 → 주식 수 변환 (정수 라운딩 / 최소금액 / 고가주 제외)
6. 3% 거래대금 상한, 청산 3일 제약
7. 주문 분할 집행
8. 실현 비중 기록 → Allocator 되먹임      ← 절대 생략 금지
```

**8번이 빠지면 RL은 학습할 수 없다.**
소액 구간에서는 5번 라운딩 때문에 목표와 실현이 크게 벌어진다.
되먹임이 없으면 Allocator는 자기가 하지 않은 행동으로 벌을 받는다.

**Executor 안에는 AI가 없다. 순수 코드만.**

## 9. ModelOps — 모델 관리

다른 에이전트가 시장을 볼 때, ModelOps는 **다른 에이전트를 본다.**

- 각 Analyst의 IC가 시간에 따라 감쇠하는지 감시 (알파 소멸)
- 재학습 시점 결정, 하이퍼파라미터 탐색
- **RL이 실제로 학습 중인지 판정** (explained_variance 등)
- 입력 분포 드리프트 감지
- **액션 반영률 감시** — 30% 미만이면 경고

> Auditor는 "왜 **돈을** 벌었나", ModelOps는 "왜 **모델이** 잘 되나"를 본다.

### Claude API 리뷰 (ModelOps가 오케스트레이션)

**Claude는 심판이 아니라 해설자다. 출력은 보상 함수에 들어가지 않는다.**
LLM 출력을 보상에 넣으면 RL이 "돈 버는 법"이 아니라 "Claude를 설득하는 법"을 배운다.

담당 3가지:
1. 일일 매매 리뷰 — 왜 이 거래가 좋았나/나빴나를 사람 말로
2. 학습 진단 — explained_variance, IC 추이, 손실곡선을 보고 "학습이 되고 있나" 판정
3. 이상 징후 서술 — 숫자로 잡히지 않는 패턴

**출력은 구조화 형식으로 강제한다:**

```json
{
  "headline": "반도체 3종목 동시 진입으로 섹터 편중 발생",
  "severity": "warn",
  "tags": ["concentration", "regime"],
  "body": "...전문..."
}
```

- `body` 전문 + 입력 스냅샷 + 모델 버전 + 토큰 비용 → `reviews` 테이블에 저장
- 대시보드에는 **`headline` 한 줄만** 표시, `severity` 에 따라 색
- 클릭하면 전문 펼침 → Decision Trace로 연결
- 결과를 `agent_cache` 에 저장한다. 같은 입력이면 캐시 반환, 재호출 금지

## 10. 학습 규약 (공통)

```
타깃      5일 후 횡단면 초과수익 z-score
검증      purged K-fold + embargo 5일
분리      국장/미장 별도 학습, IC 별도 측정
피처      전부 store.get(as_of=...) 경유
합격선    IC 0.03 (OOS, 표본 200거래일 이상)
재학습    분기 1회 또는 30일 IC 이동평균 0.01 미만
```

### 투입 방식: 만들기는 전부, 켜기는 개별로

5개 Analyst를 처음부터 전부 구현하고 점수도 모두 기록한다.
다만 **IC 0.03을 통과한 Analyst만 실제 매매 가중치를 받는다.**
통과하지 못한 것은 점수를 계속 남기되 가중치 0(관찰 모드)으로 둔다.

한꺼번에 켜면 성과가 나쁠 때 범인을 특정할 수 없다.
백테스트 IC가 0.15처럼 나오면 그것은 재능이 아니라 버그다.
