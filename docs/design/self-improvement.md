# 자기개선 루프

## 0. 먼저 인정할 것 — 자기개선은 과적합 기계다

금융 시스템에서 "스스로 개선한다"는 말은 실제로는
**같은 유한한 데이터에 대해 가설을 반복 검정한다**는 뜻이다.

과거 데이터는 5년, 약 1,250거래일뿐이다.
자동 루프가 변형 1,000개를 시도하면, 신호가 전혀 없어도 **그중 최고는 반드시 좋아 보인다.**
개선된 게 아니라 운 좋은 걸 고른 것이다.

> 시행 예산 없는 자기개선은 자기기만이다.

그래서 이 문서의 절반은 "무엇을 자동화할까"가 아니라
**"자동화를 어떻게 정직하게 만들까"** 에 관한 것이다.

## 1. 세 가지 안전장치 (이게 먼저 있어야 한다)

### ① 홀드아웃 금고

전체 기간의 마지막 구간(예: 최근 12개월)을 **금고에 넣고 탐색 중 절대 열지 않는다.**

- 탐색·튜닝·진화·피처 발굴 어디에도 쓰지 않는다
- 승격 심사 때 **딱 한 번** 연다
- 한 번 열면 소진된 것으로 간주하고, 이후 그 구간은 탐색 데이터로 강등된다
- 금고 접근은 로그로 남긴다. 누가 언제 열었는지 추적 가능해야 한다

### ② 사전등록

후보를 만들기 **전에** 평가 방법을 고정하고 커밋한다.

```
평가 지표, 검증 폴드, 표본 기간, 합격 기준, 시행 횟수 상한
```

결과를 본 뒤 기준을 바꾸는 것이 과적합의 가장 흔한 경로다.
사전등록 파일의 해시를 결과와 함께 저장한다.

#### 대조군 규칙 (2026-09-04) — 두 벤치마크, 역할이 다르다
- **개선 시행의 대조 = 매매 가능 유니버스 동일가중**(그리고 직전 채택 규칙). 우리가 살 수 있는 세계에서 이겼는가를 잰다.
- **K200(또는 KODEX200) 대비 IR 은 모든 시행 표에 함께 적되 채택 기준이 아니다.** 종료 기준(milestones.md)만 K200 을 쓴다.
- 이유: 유동시총 대용지수로 편향을 없앤 뒤에도 K200 대비 IR −3 이 남았다. 초대형주 집중 랠리에서 동일가중 24 가 지는 것은
  구조이지 알파의 부재가 아니다. 대조를 K200 으로 두면 개선이 있어도 전부 "기각" 으로 읽힌다.

#### 랭커 계열 판정 기준 (2026-09-25, 사용자 승인 "1, 2번 진행해") — 주 기준은 상위 N 포트, IC 는 해 방지

**왜.** 같은 모양이 한 주에 셋 나왔다 — 6차 G4(국장 내부자)·G7(미장 내부자)·시행 W(원피처): **IC 는 그대로이거나 내려갔는데 상위 24 수익은
세 시드 모두 올랐다.** 반대로 AJ 는 IC 가 올랐는데 박스장 상위 24 가 −7.2%p 였다. 우리가 사는 것은 맨 위 24 이고, IC 는 전 종목 순위의
평균 정확도다. 소수 종목에만 있는 신호는 IC 를 거의 못 움직이지만 그 소수가 상위 24 에 들면 포트는 움직인다. IC 로만 판정하면 그것을 버린다.

**새 등록부터**(랭커 입력·목적·모델을 바꾸는 시행) 기준 틀을 이렇게 쓴다. 이미 등록된 시행(G8·X·AQ·AR)에는 소급하지 않는다 — 결과를 본 뒤
기준을 바꾸는 것이 된다.

| | 기준 | 성격 |
|---|---|---|
| ① | 세 시드 평균 비용 후 연수익(상위 N 포트, 현행 구성) ≥ 대조 + **2%p** | 개선 주장 |
| ② | **세 시드 모두** 같은 시드 대조보다 높다(3/3) | 개선 주장 |
| ③ | 두 국면(또는 판정 창을 반으로 나눈 두 구간) 모두 ≥ 대조 − 1%p | 해 방지 |
| ④ | 주 시장 ΔIC(h5) ≥ −0.01 · 다른 시장 ΔIC ≥ −0.005 | 해 방지 |
| ⑤ | MDD 가 대조보다 2%p 넘게 깊지 않고, 연 회전 ≤ 대조 × 1.2 | 해 방지 |

- **현행 구성** = 점수 EMA5 · 상위 24 동일가중 · 완충 3N · 10세션 재조정(AO) · 편도 0.41%. 구성이 바뀌면 그 시점부터 새 등록은 새 구성으로.
- **2%p 는 시드 잡음에서 나온다** — 상위 24 포트는 시드만 바꿔도 연 3.7%p 갈린다(memory seed-noise), 세 시드 평균의 잡음 ≈ 2.1%p.
  포트 수익은 IC 보다 잡음이 커서 ②(3/3)를 같이 건다. IC 의 NW t 는 기록한다.
- 대조는 같은 시드의 현행 모델. 원천 하나(시드 하나)로 판정하지 않는다.

### ③ 시행 횟수 누적 추적

**모든 자동 시행을 하나의 카운터에 누적한다.** 실험별로 리셋하지 않는다.

- Deflated Sharpe Ratio 로 시행 횟수를 보정한 유의성을 계산한다
- 누적 시행이 많아질수록 합격선이 자동으로 높아진다
- 분기별 시행 예산을 정하고, 소진되면 다음 분기까지 탐색을 멈춘다

## 2. 자동화 계층 — 위험도 순

| 계층 | 내용 | 위험 | 상태 |
|---|---|---|---|
| **L0** | 알파 감쇠 감지 → 재학습 | 낮음 | ModelOps 에 설계됨 |
| **L1** | Selector 가중치 재진화 | 낮음 | 설계됨 |
| **L2** | 하이퍼파라미터 자동 튜닝 | 중간 | Optuna, 예산 제한 |
| **L3** | 신호 자동 발굴 | 높음 | 신규 |
| **L4** | LLM 이 코드를 수정 | 매우 높음 | 신규 |

**L0~L1 은 개선이 아니라 유지보수다.** 새 가설을 검정하지 않고,
같은 모델을 새 데이터에 맞추는 것뿐이다. 여기부터 확실히 돌려야 한다.

## 3. L3 — 신호 자동 발굴

기존 피처를 연산자 문법으로 조합해 새 알파식을 유전 프로그래밍으로 탐색한다.

```
연산자: rank, ts_mean(n), ts_std(n), delta(n), corr(x,y,n),
        scale, sign, decay_linear, ...
말단:   기존 피처 (가격, 거래량, 수급, 재무 항목)
```

### 반드시 걸어야 할 제약

**① 직교성 요구**
새 알파는 단독 IC 가 아니라 **기존 조합에 대한 잔차 IC** 로 평가한다.
기존 신호를 재발견한 것에 상을 주면 안 된다.

**② 복잡도 페널티**
식의 깊이·노드 수에 벌점. 복잡한 식일수록 과적합이다.

**③ 경제적 해석 가능성**
사람이 "왜 이게 작동하는가"를 한 문장으로 설명할 수 없는 알파는 채택하지 않는다.
설명할 수 없으면 언제 무너질지도 모른다.

**④ 시행 예산**
세대·개체 수를 시행 카운터에 그대로 누적한다.
population 100 × generation 50 = **5,000 시행**이다. 이 숫자를 정직하게 센다.

## 4. L4 — LLM 을 가설 생성기로

Claude 가 코드를 무제한 고치는 것이 아니라, **제안만 하고 승격은 사람이 한다.**

```
Auditor 귀속 결과 + 실패 사례
        ↓
Claude: "왜 이 구간에서 잃었는가" → 가설 N개 제안
        ↓
자동: 코드 생성 → 사전등록된 프로토콜로 검정
        ↓
결과 요약 → 사람 승인 → shadow → 승격
```

### 위험 지점

**Claude 가 결과를 보고 다시 제안하는 순환이 가장 빠르게 과적합한다.**
사람의 개입 없이 제안→검정→제안 루프를 돌리면, Claude 는 사실상
검증 데이터에 대한 경사하강을 수행하는 옵티마이저가 된다.

제약:
- 한 사이클당 제안 상한 (예: 5개)
- 사이클 사이에 **사람 검토 필수**
- Claude 에게 **홀드아웃 결과를 절대 보여주지 않는다**
- 제안·검정·결정 전 과정을 로그로 남긴다
- 모든 시행을 §1③ 카운터에 누적

## 5. 가장 값진 자기개선은 따로 있다

### 시간이 유일한 진짜 신규 데이터다

과거 5년은 아무리 다시 갈아도 새 정보가 안 나온다.
반면 **shadow 와 실전은 매일 오염되지 않은 관측 하나씩을 만든다.**

- 룰 베이스라인과 후보 정책을 **항상 병주**한다
- 매일 두 정책의 결정 차이와 실현 손익 차이를 기록한다
- 실전 표본이 쌓여 통계적으로 유의해지면 그때 교체한다

느리지만 이것만이 정직하다. **자기개선 엔진의 본체는 이쪽이다.**

### 데이터 소스 추가가 알고리즘 개선보다 낫다

지금 병목은 알고리즘이 아니라 정보량이다.
EDGAR 공시, FINRA 공매도처럼 **새 정보원을 붙이는 것**이
같은 데이터에 알고리즘을 100번 돌리는 것보다 기대값이 훨씬 높다.

### 레짐 조건부 가중치

"언제 어느 Analyst 를 믿을 것인가"를 배우는 것은
탐색 공간이 작으면서 실질적인 개선 축이다.
가중치 벡터 하나가 아니라 레짐별 가중치 벡터를 둔다.

## 6. 절대 자동화하지 않는 것

- **보상 함수 계수 자동 조정** — 시스템이 자기 성적표를 고치는 것이다
- **홀드아웃을 본 뒤 기준 완화**
- **성과가 나올 때까지 반복** — 선행 프로젝트의 실패 방식 그대로다
- **사람 승인 없는 실전 승격**
- **킬스위치·리스크 가드 파라미터의 자동 변경**

---

## 7. 대시보드에 반드시 표시할 것

자기개선을 켜면 **누적 시행 횟수가 성과 지표만큼 중요해진다.**

- 분기 누적 시행 횟수 / 예산
- 홀드아웃 금고 개봉 이력
- Deflated Sharpe Ratio (시행 보정 후 유의성)
- 승격 제안 대비 실제 승격 비율
- 승격된 변경의 사후 성과 (제안 시점 기대치 대비)

마지막 항목이 자기개선 루프 자체의 성적표다.
**승격한 변경들이 실제로는 개선이 아니었다면, 루프를 멈춰야 한다.**

- `tools/tally_trials.py` — 소급 집계 (2026-08-26 적재: **누적 163회**, 근거는 각 행 detail)

- 학습 탭 §7 패널 (`/api/learning/research-ledger`) — 누적/예산·DSR·금고 이력·승격 성적표 자리

### ① 홀드아웃 금고 — 다음 단계

**금고는 2026-07-01 이후다.** "최근 12개월"을 소급 지정할 수 없다 —
2026-06-30 까지는 학습·IC·진화가 이미 봤다. 아직 어떤 탐색도 안 본 구간이
유일하게 정직한 금고이고, 시간이 지나며 자란다.

1. `Store` 에 목적 컨텍스트를 추가한다: `Store(root, purpose="explore")`.
   기본은 `purpose=None`(운영·라이브 — 게이트 없음).
2. `store.get()` 이 `purpose=="explore"` 이고 요청 구간이
   `research.holdout.start` 를 침범하면 `HoldoutViolation` 을 던진다.
   as_of 만이 아니라 **lookback 이 닿는 구간**도 검사한다.
3. 탐색 도구(measure_ic·run_evolution·train_rl·백테스트류)는 전부
   `purpose="explore"` 로 Store 를 연다 — 기본값 논쟁을 없애기 위해
   tests/invariants 에 "탐색 도구가 purpose 없이 Store 를 열면 실패" 검사를 둔다.
4. 승격 심사만 `store.open_holdout(reason=...)` 로 연다. 이 호출이
   `holdout_access` 에 1행을 남기고, 열람 구간은 소진으로 강등된다
   (config `research.holdout.start` 를 열람 끝+1일로 올리는 정정본).

#### 금고 앞당김 개봉 (2026-09-30 초안 — `docs/protocols/vault-early-open-2026-10.md`)

사용자 결정(2026-09-29 "shadow 먼저 + 금고 앞당김"). 원래 한 번(2026-11-23, 창 7/1~11/13)이던 개봉을 둘로 나눈다.
- **early** 7/1~9/30(국장 62세션) — AQ·AR·AS·BD + BE2 를 한 번에. 판정은 h5 라벨이 닫힌 10/13 이후.
- **second** 10/1~11/13(30세션) — 11/23 에 한 번. BE2 확인(early 통과 시)과 BD(early 보류 시)만.
- 시행별 기준은 각 등록 문서 그대로이고, 앞당김 문서가 **창만** 바꾸며 그 문서들의 해시를 고정한다. 판정부(`tools/vault_judge.py --window`)는
  앞당김 문서의 해시가 코드에 고정되기 전에는(초안) 굽기·판정을 모두 거부하고, 이미 연 창과 겹치는 창을 다시 열지 않는다.
- 개봉 뒤 7/1~9/30 은 탐색 자료로 강등(`research.holdout.start` → 2026-10-01 정정본).

### ② 사전등록 — 다음 단계

registry-2(4b45701) 에서 이미 한 번 실행한 방식의 일반화다.

1. `docs/protocols/<이름>.md` — 평가 지표·폴드·기간·합격 기준·시행 상한을
   후보 생성 **전에** 커밋한다.
2. `tools/preregister.py` 가 sha256 16자리를 찍고 config
   (`research.protocol.<이름>`) 에 심는다.
3. 평가 도구는 `--protocol <이름>` 없이는 `--save` 를 거부한다.
   결과 행(research_trials·analyst_weights)에 protocol_hash 가 같이 저장된다.
4. 문서 해시가 심긴 값과 다르면(사후 수정) 도구가 멈춘다 — 결과를 본 뒤
   기준을 바꾸는 길을 코드로 막는다.

### ③ 시행 카운터 — 남은 것

카운터·DSR·소급 집계·화면은 들어왔다. 남은 배선:

1. measure_ic `--save` · run_evolution · train_rl 이 끝날 때
   research_trials 에 1행(또는 개체 수만큼)을 자동 append.
2. 분기 예산 소진 시 탐색 도구가 시작을 거부한다(`--override-budget` 는

## 10. 검정 표준 v2 — 짧은 금고의 검정력 문제 (2026-10-10, 사용자 "이렇게 해보자")

**문제.** 지금까지 주 기준은 "상위 24종목 포트의 비용 후 연수익 차" 였다. 62세션 금고에서 그 차의 우연 변동은 연 ±15~20%p 라
"+2%p 우세" 를 진짜 효과가 있어도 거의 못 넘는다(vault-early-open §판정력: "이 금고는 +2%p 차이를 통계적으로 가를 수 없다").
**10/13 판정 기준은 이미 고정이라 바꾸지 않는다.** 아래는 **새 등록부터** 적용한다.

1. **주 기준 = 검정력 높은 지표.** 종목 × 세션 단위 시험 — 빼기 규칙은 "뺀 종목의 다음 5세션 초과"(TF 원리 시험), 점수·피처는 IC·편 IC·10분위 초과.
   포트 수익은 **해 방지**(뒤집히지 않음: ≥ 대조 − 여유, 시드 다수, 두 구간)로만 쓴다.
2. **잡음 줄이기를 기본값으로.** 짝 비교(처리·대조 같은 종목군·같은 시드) · 재조정 위상 10벌 평균(판정 숫자는 평균, 위상 고르기 금지) · 시드 5 · 가능하면 넓은 포트(N100).
3. **등록 전 검정력 계산 의무화**(`tools/power_check.py`). 등록 문서에 "이 창·이 포트에서 최소 탐지 효과(80% 검정력, 양측 5%)" 를 적는다.
   기대 효과(탐색 결과의 절반으로 깎은 값)가 그보다 작으면 **짧은 금고에 걸지 않고** 전방 장부(4)로 보낸다.
4. **전방 장부 + 순차 검정**(`quant_rl_trading/modelops/sequential.py`). shadow 장부 짝(처리 − 대조)의 일 초과수익에 **언제 봐도 유효한 신뢰구간**
   (asymptotic confidence sequence, Waudby-Smith 등 2021)을 매일 갱신한다. 하한 > 0 이면 "우세 확정", 상한 < 0 이면 "열위 확정", 그 사이는 "모름".
   고정 길이(62세션)로 끊지 않는다 — 매일 봐도 1종 오류가 커지지 않는 구간이라 엿보기가 허용된다. 대시보드 Fund 탭에 장부 짝마다 표시.
5. **적용 경로**: 실전 배선이 준비된 시행만 금고에 건다(AR·AS 처럼 통과해도 못 쓰는 일을 막는다) — 사용자는 이번엔 고르지 않았다. 권고로만 둔다.
