# LS 증권 API 연동

**이 문서는 확인해야 할 항목의 목록이지, 확정된 사양이 아니다.**
API 스펙은 변경되고 계좌 유형·상품별로 다르다. LS_KR / LS_USA 코드와 공식 문서로
실측 확인한 뒤 이 문서를 채운다.

백테스트가 실제 API 제약과 어긋나면 M3에서 그대로 터진다.

---

## 1. 반드시 실측할 것

### 인증
- 토큰 유효기간과 갱신 주기
- 동시 세션 제한 (대시보드와 워커가 같은 계정을 쓰면 충돌하는지)
- 모의투자와 실전의 엔드포인트·키 차이

### 레이트리밋
- 초당·분당 호출 상한 (조회/주문 각각)
- 상한 초과 시 응답 코드와 차단 시간
- **Analyst 9명이 200종목을 조회할 때 상한에 걸리는지** ← 설계에 직결

레이트리밋이 빡빡하면 Session 타임라인을 조정하거나 조회를 배치화해야 한다.

### 주문
- 지원 주문 유형 (지정가, 시장가, 조건부, IOC/FOK)
- 최소 주문 단위·금액
- 정정·취소 API 와 그 지연
- 부분체결 통보 방식 (폴링인지 이벤트인지)
- 주문 번호 체계 — **client order id 를 우리가 지정할 수 있는지**
  지정 불가능하면 멱등성을 다른 방식으로 확보해야 한다 (로컬 주문 원장 대조)

### 미국주식
- 거래 가능 시간대 (정규장 / 프리·애프터 / 주간거래 지원 여부)
- 통화 결제 방식 — 원화 자동환전인지 달러 예수금인지
- 환전 API 존재 여부와 스프레드
- 결제 주기 (T+1인지 T+2인지 — 최근 변경됨)
- 소수점 매매 지원 여부 ← **지원되면 소액 구간 설계가 크게 달라진다**

### 조회
- 실시간 시세 방식 (REST 폴링 / WebSocket)
- 수급 데이터 제공 범위와 갱신 주기 (장중 잠정치 제공 여부)
- 과거 데이터 조회 한도 (한 번에 며칠, 총 몇 년)
- **5년치 전종목 백필이 API 한도 내에서 가능한지** ← M1 일정에 직결

가능하지 않으면 별도 데이터 소스가 필요하다. 이 확인이 M1 착수 전에 끝나야 한다.

## 2. 안전장치

### 모의/실전 구분
- 환경변수로 명시하고 **부팅 시 로그에 크게 출력**
- 실전 키와 모의 키를 다른 Secret 이름으로 분리
- 실전 모드일 때 첫 주문 전 1회 확인 절차 (소액 구간 초기)

모의인 줄 알고 실전을 돌리는 것이 이 분야에서 가장 흔한 사고다.

### 장애 대응
- 타임아웃·재시도 정책 (지수 백오프)
- **주문 API 는 재시도가 위험하다.** 응답을 못 받았을 뿐 체결됐을 수 있다.
  재시도 전 반드시 주문 조회로 상태를 확인한다
- 연속 실패 시 킬스위치 연동

### 대사(reconciliation)
- **매일 증권사 잔고와 로컬 포지션을 대조한다**
- 불일치 시 즉시 킬스위치 발동
- 대조 결과를 리포트에 포함

## 3. LS_KR / LS_USA 에서 이식할 것

이미 실전 검증된 부분이다. 다시 만들지 않는다.

- 토큰 갱신 로직
- 재시도·백오프
- 응답 파싱·정규화
- 휴장일 캘린더, 서머타임 처리
- 에러 코드 매핑

이식 시 커밋 메시지에 출처를 남긴다: `port(collectors): LS_KR 토큰 갱신 이식`

**학습·상태설계·보상 관련 코드는 가져오지 않는다** (CLAUDE.md 참고 규칙).
