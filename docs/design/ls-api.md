# LS 증권 API 연동

**아래 §0 은 확정된 사양이다. §1 부터는 아직 확인해야 할 항목의 목록이다.**
API 스펙은 변경되고 계좌 유형·상품별로 다르다. LS_KR / LS_USA 코드와 공식 문서로
실측 확인한 뒤 이 문서를 채운다.

백테스트가 실제 API 제약과 어긋나면 M3에서 그대로 터진다.

## 0. 미국주식 TR — 확정 (2026-08-15)

이 저장소에서 **문서만 보고 내린 결론이 여러 번 틀렸다**(FRED release_id 짐작,
ECOS 503 오판, `t1511` 경로, `t8419`↔`t8418`). 그래서 아래는 **근거의 등급을
칸으로 갈라 적는다.** 등급이 낮은 줄은 아직 사실이 아니라 가설이다.

| 등급 | 뜻 |
|---|---|
| **실호출** | 이 저장소에서 실제로 호출해 응답을 받았다 |
| **공식목록** | LS 개발자포털 카탈로그 API 응답에서 읽었다 (`openapi.ls-sec.co.kr/api/apis/public`) |
| **샘플코드** | 서드파티 샘플에서 읽었다 — **검증 안 됨** |

### 0-1. 경로와 TR 전체 목록 — 공식목록 + 실호출

포털 카탈로그가 내놓은 목록과 빈 블록 실호출 결과가 **완전히 일치한다.**
해외주식은 아래 8개가 전부다. 목록에 없는 코드는 전부 `IGW00215`(유효하지
않은 TR CD)로 떨어진다.

| 경로 | TR | 이름 | 초당한도 | 근거 |
|---|---|---|---|---|
| `/overseas-stock/accno` | `COSOQ02701` | 해외주식 예수금 조회 | 1 | 실호출 ✅ 데이터 정상 |
| | `COSOQ00201` | 해외주식 종합잔고평가 | 1 | 실호출 ✅ (보유 0 → `02679`) |
| | `COSAQ00102` | 해외주식 계좌주문체결내역조회 | 1 | 실호출 ✅ (주문 0 → `02679`) |
| | `COSAQ01400` | 예약주문 처리결과 조회 | 1 | 실호출(존재만) |
| `/overseas-stock/order` | `COSAT00301` | 미국시장주문 (신규·**취소**) | 10 | 실호출(존재만) |
| | `COSAT00311` | 미국시장정정주문 | 10 | 실호출(존재만) |
| | `COSAT00400` | 해외주식 예약주문 등록·취소 | 1 | 실호출(존재만) |
| | `COSMT00300` | 해외증권 매도상환주문(미국) | 1 | 실호출(존재만) |

**주문 TR 은 "존재 여부"만 확인했다.** 확인 방법은 빈 블록
(`{f"{tr}InBlock1": {}}`)을 보내는 것이다 — 없으면 `IGW00215`, 있으면
`09604`(입력 데이터 포맷이 맞지않습니다)가 온다. **필드를 채우면 그 순간
진짜 주문이 나간다.** 채우지 마라.

시세·차트는 이미 수집기가 쓴다: `/overseas-stock/market-data` =
`g3101|g3102|g3104|g3106|g3190`, `/overseas-stock/chart` =
`g3103|g3202|g3203|g3204`. 실시간은 `/websocket/overseas-stock` =
`AS0`(주문접수) `AS1`(체결) `AS2`(정정) `AS3`(취소) `AS4`(거부) + `GSC` `GSH`.

### 0-1-1. 국장 차트도 경로가 따로다 — `t8410` 은 `/stock/chart` 다

미장이 `market-data`/`chart` 로 갈리는 것과 **똑같이 국장도 갈린다.**
`market_collector.py` 가 일봉 `t8410` 을 `/stock/market-data` 로 부르고 있어서
**그 메서드는 한 번도 성공한 적이 없었다** (실측 2026-08-15).

```
/stock/market-data + t8410  →  HTTP 500 {"rsp_cd":"IGW00215", ...}  유효하지 않은 TR CD
/stock/chart       + t8410  →  200, 정상 200행
```

국장 일봉이 KRX Open API 로 들어오는 덕에 아무도 몰랐다. `PATH_FLOW`
(`/stock/frgr-itt`)와 같은 함정이고 증상까지 같다 — **경로가 틀리면 "TR 이
없다"** 고 나와서 "LS 에는 그 데이터가 없다" 는 잘못된 결론으로 간다.

상수는 `ls_client.PATH_CHART` 다. 경로는 고쳤지만 `collect_ohlcv` 는 막아
두었다 — 국장 일봉의 정본은 KRX 이고, `prices` 자연키가
`(entity_id, valid_from)` 이라 두 소스가 같이 쓰면 어느 값이 남는지가 **수집
순서에 달린다.** 쓰려면 정본을 먼저 정해라.

`sujung` 을 `"Y"`/`"N"` 두 번 불러 나누면 **기업행위 조정계수**가 나온다.
`collectors/corporate_actions.py` 가 이 경로를 쓴다. `qrycnt` 는 3000 을 줘도
**501행에서 끊기므로**(실측) 5년치는 `edate` 를 밀며 3페이지를 넘겨야 한다.

### 0-2. `CIDBQ*` 는 해외주식이 아니다 — 해외**선물**이다

선행 프로젝트(`ls_us_rl_trader/broker/ls_client.py:13-15`)가 `CIDBQ01500` 을
"해외주식 잔고"로 적어 두었다. **틀렸다.** 포털 카탈로그상 `CIDBQ01400·01500·
01800·02400·03000·05300` 은 `/overseas-futureoption/accno`(해외선물 계좌)
소속이다. 그래서 `/overseas-stock/accno` 로 부르면 TR 이 없다고 나온다.

이 한 줄을 몰라서 "경로가 틀렸나" 를 오래 뒤졌다. 짐작으로 TR 을 찍는 대신
**카탈로그 API 를 먼저 받아라**: `GET openapi.ls-sec.co.kr/api/apis/public?size=1000`
— 인증 없이 41개 API 그룹·364개 TR 의 소속 경로와 초당한도가 전부 나온다.

### 0-3. 예수금 — 실호출 ✅

```
COSOQ02701InBlock1 = {"RecCnt": 1, "CrcyCode": "USD"}
```

2026-08-15 실계좌 응답:

| 블록 | 필드 | 값 | 뜻 |
|---|---|---|---|
| OutBlock3 | `FcurrDps` | **9.4900** | 외화예수금 (USD) |
| | `FcurrOrdAbleAmt` | 9.4900 | 주문가능금액 (USD) |
| | `FcurrMxchgAbleAmt` | 9.4900 | 환전가능금액 (USD) |
| | `BaseXchrat` | 1414.9000 | 기준환율 |
| OutBlock4 | `WonDpsBalAmt` | 5 | **원화** 예수금 (원) |

**`t0424`(국장 잔고)를 미장 계좌로 불렀을 때 나오던 `5` 의 정체가 이것이다** —
단위 불명의 무언가가 아니라 **원화 예수금 5원**이다. 달러 잔고는 국장 TR 로는
보이지 않는다. 미장 현금은 `COSOQ02701` 로만 읽어라.

### 0-4. 잔고·체결내역 — 실호출 ✅ (단, 빈 계좌)

```
COSOQ00201InBlock1 = {"RecCnt":1, "BaseDt":"", "CrcyCode":"USD", "AstkBalTpCode":"00"}
COSAQ00102InBlock1 = {"RecCnt":1, "QryTpCode":"1", "BkseqTpCode":"2", "OrdMktCode":"82",
                      "BnsTpCode":"0", "IsuNo":"", "SrtOrdNo":0, "OrdDt":"", "ExecYn":"2",
                      "CrcyCode":"USD", "ThdayBnsAppYn":"0", "LoanBalHldYn":"0"}
```

둘 다 `rsp_cd=02679 조회내역이 없습니다` 를 돌려준다. 보유종목 0·주문 0 이므로
**정상이다.** 그래서 **출력 블록의 실제 모양은 아직 못 봤다** — 아래 필드표는
샘플코드 등급이고, 첫 미장 주문 뒤에 실물로 다시 확인해야 한다.

- `COSOQ00201OutBlock2.WonDpsBalAmt` — 원화예수금 · **샘플코드**
- `COSOQ00201OutBlock4[]` — 보유종목. `CrcyCode` `ShtnIsuNo` `AstkBalQty`
  `AstkSellAbleQty` `FcstckUprc` `OvrsScrtsCurpri` `PnlRat` · **샘플코드**
- `COSAQ00102OutBlock3[]` — 주문·체결. `OrdNo` `ShtnIsuNo` `OrdPtnCode` `OrdQty`
  `OvrsOrdPrc` `UnercQty` `OrgOrdNo` `OrdTime` · **샘플코드**

> ⚠️ 선행 프로젝트는 `COSOQ00201` 의 보유종목을 **OutBlock3** 에서 읽는다
> (`ls_client.py:305`). 샘플은 **OutBlock4** 다. 둘 중 하나는 틀렸고,
> 잔고가 비어 있는 지금은 어느 쪽인지 가릴 수 없다. **이식할 때 그대로
> 베끼지 마라** — 실물 응답을 보고 정하라.

> ⚠️ `02679` 는 `OK_CODES` 에 없어서 `LSClient` 가 예외를 던진다. 빈 계좌 조회가
> 오류로 보인다. 미장 잔고를 배선할 때 "조회내역 없음 = 빈 결과" 로 다뤄야 한다.

### 0-5. 주문 4종 — 필드는 **아직 검증 안 됐다**

**존재는 실호출로 확인했고, 필드 구성은 보내 본 적이 없다.**

포털이 요청 예제를 공개한 것은 `COSAT00301` 하나뿐이다 (공식목록):

```json
{"COSAT00301InBlock1": {"RecCnt":1, "OrdPtnCode":"02", "OrdMktCode":"82",
 "IsuNo":"PLTR", "OrdQty":5, "OvrsOrdPrc":70, "OrdprcPtnCode":"00", "BrkTpCode":""}}
```

`COSAT00311`·`COSAT00400`·`COSMT00300` 은 **포털에 예제가 없다**
(`/api/apis/guide/tr/{api_id}` 응답의 `reqExample` 이 `null`). 필드별 상세표를
내주는 공개 엔드포인트도 찾지 못했다(§0-12).

아래는 서드파티 샘플(`github.com/teranum/ls-openapi-samples`,
`Python/51. 해외주식-주문종합.py`)에서 읽은 것이다 — **샘플코드 등급.**

| 동작 | TR | 핵심 필드 |
|---|---|---|
| 매수 | `COSAT00301` | `OrdPtnCode="02"`, `OrgOrdNo=0` |
| 매도 | `COSAT00301` | `OrdPtnCode="01"`, `OrgOrdNo=0` |
| **취소** | `COSAT00301` | `OrdPtnCode="08"`, `OrgOrdNo=원주문번호`, `OrdQty=0`, `OvrsOrdPrc=0`, `IsuNo=""`, `OrdMktCode=""` |
| **정정** | `COSAT00311` | `OrdPtnCode="07"`, `OrgOrdNo=원주문번호`, `OrdQty=0`, `OvrsOrdPrc=정정가`, `OrdprcPtnCode=""` |
| 체결조회 | `COSAQ00102` | `ExecYn` — `0`전체 `1`체결 `2`미체결 |

**취소는 별도 TR 이 아니다.** 국장의 `CSPAT00801` 같은 취소 전용 TR 이
미장에는 없고, 신규주문과 같은 `COSAT00301` 에 `OrdPtnCode=08` 로 낸다.
`COSAT00311` 은 **정정 전용**이다.

공통 코드값 (샘플코드):
`OrdMktCode` `81`=뉴욕 `82`=나스닥 · `OrdprcPtnCode` `00`=지정가 `03`=시장가 ·
`AstkBalTpCode` `00`=전체 `10`=일반 `20`=소수점 · `BkseqTpCode` `1`=역순 `2`=정순

#### 국장과 미장의 매수·매도 필드 — **틀리면 반대로 산다**

`broker/ls_order.py` 를 미장으로 늘릴 때 여기가 첫 번째 함정이다.

| | 국장 `CSPAT00601` | 미장 `COSAT00301` |
|---|---|---|
| 매매구분 **필드명** | `BnsTpCode` | **`OrdPtnCode`** |
| 매수 | `"2"` | **`"02"`** |
| 매도 | `"1"` | **`"01"`** |
| 취소 | 별도 TR `CSPAT00801` | **같은 필드 `"08"`** |
| 정정 | 별도 TR `CSPAT00701` | 별도 TR `COSAT00311`, `OrdPtnCode="07"` |
| 종목코드 | `IsuNo` = `A` + 6자리 (`isu_code()`) | `IsuNo` = 심볼 그대로 (`TSLA`) — **`A` 붙이지 마라** |
| 가격 | `OrdPrc` (정수 원) | **`OvrsOrdPrc`** (float 달러) |
| 호가유형 | `OrdprcPtnCode` `00`/`03` | `OrdprcPtnCode` `00`/`03` (같다) |
| 시장 | 없음 | **`OrdMktCode`** `81`/`82` 필수 |
| 신용·조건 | `MgntrnCode` `LoanDt` `OrdCndiTpCode` | **없음.** 대신 `RecCnt` `BrkTpCode` |

숫자 규약(2=매수, 1=매도)은 다행히 국장과 같다. **다른 것은 필드 이름과
자릿수다** — `BnsTpCode` 를 그대로 보내면 미장은 매매구분을 못 읽는다.

> ⚠️ **`OrdPtnCode` 와 `OrdprcPtnCode` 는 다른 필드다.** 세 글자(`prc`) 차이인데
> 하나는 매수/매도, 하나는 지정가/시장가다. 바꿔 쓰면 `"00"`(지정가)이
> 매매구분 자리에 들어간다.

### 0-6. 체결조회 — 국장 `t0425` 와 모양이 다르다

> ✅ **배선 완료** — `broker/fills.py` 가 `PendingFill.market` 으로 TR 을 고른다(§0-11).

원래 `broker/fills.py` 는 국장 전용이었다(`TR_FILLS = "t0425"`). 미장은 `COSAQ00102`
하나로 미체결·체결을 다 받고, 세 가지가 다르다.

| | 국장 `t0425` | 미장 `COSAQ00102` |
|---|---|---|
| 블록 접미사 | `t0425InBlock` (**접미사 없음**) | `COSAQ00102InBlock1` |
| 입력 | `expcode` `chegb` `medosu` `sortgb` `cts_ordno` (5개) | `RecCnt` `QryTpCode` `BkseqTpCode` **`OrdMktCode`** `BnsTpCode` `IsuNo` `SrtOrdNo` `OrdDt` `ExecYn` **`CrcyCode`** `ThdayBnsAppYn` `LoanBalHldYn` (12개) |
| 출력 | `t0425OutBlock1[]` | `COSAQ00102OutBlock3[]` |
| 주문번호 | `ordno` (소문자) | `OrdNo` / `OrgOrdNo` |
| 누적체결 | `cheqty` `chevol` `execqty` `ordcheqty` | `ExecQty` `AllExecQty` · 미체결잔량 `UnercQty` |
| 체결가 | `cheprice` `cheprc` … (원, 정수) | `OvrsExecPrc` / `OvrsOrdPrc` (**달러, 소수**) |
| 전종목 한 번에 | 예 | **아니오 — `OrdMktCode` 필수라 `81`·`82` 를 각각 부른다** |

배선상 걸리는 것 셋:

1. **시장을 나눠 두 번 부른다.** `sync_fills` 는 TR 을 한 번 부르고 전 주문을
   `by_ordno` 로 대조하는 구조다. 미장은 뉴욕·나스닥을 각각 불러 합쳐야 한다.
   초당 1건 한도라 **한 사이클에 2초**가 든다.
2. **`_index_by_ordno` 는 이미 `OrdNo` 를 본다** — 대문자 키를 후보에 넣어 둔
   덕에 그대로 쓸 수 있다. 반면 `_first_numeric` 의 후보 목록은 전부 국장
   소문자 이름이라 미장 이름(`ExecQty`/`OvrsExecPrc`)을 더해야 한다.
3. **`price <= 0` 검사가 소수점에서도 유효한지.** 국장은 정수 원이라 0 이
   "못 읽음"의 신호였는데, 달러는 $0.0073 짜리 워런트도 실재한다(§0-8).
   0 판정 자체는 그대로 두되 **정수 캐스팅을 어디에도 넣지 마라.**

### 0-7. 지문 고정을 시장별로 나눠야 한다

> ✅ **적용됨** — `execution.live_account_fingerprint_us` 로 갈랐다(§0-11).

`execution.live_account_fingerprint` 는 스칼라 한 칸이고 지금 국장 지문
(`aa303b375a64`)이 들어 있다. 미장은 **별도 appkey** 라 지문이 다르다
(`20cf550a301f`, `.env` 의 `LS_US_ACCOUNT_KIND=real`).

한 칸으로는 둘을 동시에 고정할 수 없다. **시장별 맵으로 바꾸는 것을 권한다**:

```yaml
live_account_fingerprint:
  KR: "aa303b375a64"
  US: "20cf550a301f"
```

빈 칸이면 고정 안 함이라는 지금 규칙은 유지하되, **"그 시장 키가 아예 없으면
거부"** 로 둬야 한다. 스칼라를 그대로 두고 미장을 얹으면 둘 중 하나는
반드시 고정이 풀린다 — 그게 "모의인 줄 알았다" 를 막는 유일한 장치다.

### 0-8. USD 9.49 로 살 수 있는가 — 실측 ✅

창고 실측(2026-08-12 종가, 미장 6,647종목):

**살 수 있다.** 유동성 있는 종목만 봐도 288개가 1주 $9.49 안에 들어온다

`execution.max_adv_ratio`·분할집행은 이 자본 구간에서 무의미하다 — 실질
제약은 "1주 = 포트폴리오 100%" 다. 미장 검증은 **한 종목 1주**가 한계이고,
그 이상은 추가 환전 없이는 불가능하다.

가장 싼 쪽(US:LTRYW $0.0073 등)은 전부 워런트(`W` 접미)다. 유니버스에
워런트가 섞여 있다는 뜻이라 **미장 후보 선정 전에 종목 유형 필터가 필요하다**
— `executor/ticks.py` 모듈 docstring 이 국장 ETF/ETN 을 두고 걱정한 것과 같은
문제가 미장에선 이미 실재한다.

> ⚠️ 샘플의 `COSAT00301InBlock1` 에는 **`OrgOrdNo` 가 있고 포털 예제에는 없다.**
> 선행 프로젝트 본문에도 없다(`ls_client.py:355-364`). 신규주문에 필수인지

### 0-10. 미장 시세는 호가를 주지 않는다 — 실호출 ✅

2026-08-15 실측. `g3104`(현재가)·`g3101`(단건조회) **어디에도 최우선호가가
없다.** `g3104` 의 `bidlotsize`/`asklotsize` 는 호가 **수량 단위**이고 값이
전부 `1` 이다 — 이걸 호가 가격으로 읽으면 $1 짜리 지정가가 나간다.

결과: 미장 기준가는 **현재가로 물러설 수밖에 없다.** 매수 즉시체결을
기대하면 안 되고, 지정가가 안 걸려 미체결로 남을 수 있다. 호가는
`/websocket/overseas-stock` 의 `GSH`(호가) 실시간에나 있다.

**반대로, 호가단위는 짐작할 필요가 없다.** `g3104` 가 종목별 `untprc` 를 준다:

| 종목 | 종가 | `untprc` | `floatpoint` |
|---|---|---|---|
| AAPL | $305.26 | 0.0100 | 4 |
| WEN | $8.65 | 0.0100 | 4 |
| BRK.A | $762,000 | 0.01 | 2 |
| LTRYW | $0.0070 | **0.0001** | 4 |

`executor/ticks.py` 를 미장에 쓸 수 없는 이유는 표가 원화 전용이라서만이
아니라 `tick_size()` 가 **`int` 를 돌려주기** 때문이다 — $0.01 은 거기서
표현이 안 된다. 표를 새로 만드는 대신 **LS 가 준 값을 쓴다.**
`sellonly`(매수금지)·`suspend`(거래정지)도 같은 응답에 있다.

**주문시장코드도 시세로 확인한다.** 틀린 `exchcd` 로 부르면 "해당종목이
없습니다" 가 온다(실측: AAPL·`81` → 없음, `82` → 정상). 그래서 82→81 순으로
시도해 **응답이 온 쪽을 그대로 `OrdMktCode` 에 넣는다.**

### 0-13. 분봉 TR — 국장 `t8412` · 미장 `g3203` (실측 2026-08-18)

| | TR | 경로 | trName |
|---|---|---|---|
| 국장 N분 | `t8412` | `/stock/chart` | 주식차트(N분) |
| 미장 N분 | `g3203` | `/overseas-stock/chart` | 차트NMIN 조회 |
| 미장 N틱 | `g3202` | `/overseas-stock/chart` | 차트NTICK 조회 |

카탈로그(`GET openapi.ls-sec.co.kr/api/apis/public`)의 `trName` 으로 확인하고
**실계좌 키로 직접 호출**했다. `ncnt` 1/5/15/60/240 전부 응답이 왔다
(국장 005930, 미장 AAPL).

**`g3202` 를 N분봉으로 적어 둔 주석이 저장소에 있었고 틀렸다.** 그건 N틱이다.
없는 TR 은 에러가 나서 바로 알지만 **있는데 뜻이 다른 TR 은 200 을 주고 봉을
준다** — 틱을 분봉으로 알고 창고에 넣으면 아무도 모른다. 이 표가 `t8410`
경로 사고(0-1-1)와 같은 자리에 있는 이유다.

#### 미장 `loctime` 은 거래소 현지시간이다

KST 가 아니다. 실측으로 확인했다 — UTC 07:24 에 `loctime="031900"` 이고
같은 응답의 `timediff` 가 −13 이라, 오프셋 −4(EDT)로 환산하면 UTC 07:19 로
맞아떨어진다.

**다만 코드는 `timediff` 를 읽지 않는다.** `zoneinfo.ZoneInfo` 로 거래소
지역시각을 만들고 `.astimezone(UTC)` 로 바꾼다
(`intraday_collector._local_timestamp`, `market_hours.SPECS` 의 timezone 을
재사용). 이유 둘:

- `timediff` 는 LS 문서에 정의가 없다. 값의 의미를 매번 믿어야 한다
- tz 데이터베이스는 서머타임 규칙이 바뀌어도 라이브러리가 따라간다.
  `market_hours.py`·`publication.py` 가 이미 같은 원칙을 쓴다 — **시간대를
  다루는 방법이 파일마다 다른 것이 제일 나쁘다**

`timediff` 는 "loctime 이 현지시간이 맞다" 를 확인하는 근거로만 썼다.

어느 쪽이든 **오프셋을 상수로 박지 마라.** 미국은 서머타임이 있어서 1년에
두 번, 특정 날짜에만 한 시간씩 틀어진다 — 그런 결함은 몇 달 뒤에 발견되고
그때는 이미 데이터가 오염돼 있다.

## 1. 반드시 실측할 것

### 인증
- 토큰 유효기간과 갱신 주기
- 동시 세션 제한 (대시보드와 워커가 같은 계정을 쓰면 충돌하는지)
- 모의투자와 실전의 엔드포인트·키 차이

### 레이트리밋
- 초당·분당 호출 상한 (조회/주문 각각)
- 상한 초과 시 응답 코드와 차단 시간
- **Analyst 9명이 200종목을 조회할 때 상한에 걸리는지** ← 설계에 직결

레이트리밋이 빡빡하면 Session 타임라인을 조정하거나 조회를 배치화해야 한다.

### 주문
- 지원 주문 유형 (지정가, 시장가, 조건부, IOC/FOK)
- 최소 주문 단위·금액
- 정정·취소 API 와 그 지연
- 부분체결 통보 방식 (폴링인지 이벤트인지)
- 주문 번호 체계 — **client order id 를 우리가 지정할 수 있는지**
  지정 불가능하면 멱등성을 다른 방식으로 확보해야 한다 (로컬 주문 원장 대조)

### 미국주식
- 거래 가능 시간대 (정규장 / 프리·애프터 / 주간거래 지원 여부)
- 통화 결제 방식 — 원화 자동환전인지 달러 예수금인지
- 환전 API 존재 여부와 스프레드
- 결제 주기 (T+1인지 T+2인지 — 최근 변경됨)
- 소수점 매매 지원 여부 ← **지원되면 소액 구간 설계가 크게 달라진다**

### 조회
- 실시간 시세 방식 (REST 폴링 / WebSocket)
- 수급 데이터 제공 범위와 갱신 주기 (장중 잠정치 제공 여부)
- 과거 데이터 조회 한도 (한 번에 며칠, 총 몇 년)
- **5년치 전종목 백필이 API 한도 내에서 가능한지** ← M1 일정에 직결

가능하지 않으면 별도 데이터 소스가 필요하다. 이 확인이 M1 착수 전에 끝나야 한다.

## 2. 안전장치

### 모의/실전 구분
- 환경변수로 명시하고 **부팅 시 로그에 크게 출력**
- 실전 키와 모의 키를 다른 Secret 이름으로 분리
- 실전 모드일 때 첫 주문 전 1회 확인 절차 (소액 구간 초기)

모의인 줄 알고 실전을 돌리는 것이 이 분야에서 가장 흔한 사고다.

### 장애 대응
- 타임아웃·재시도 정책 (지수 백오프)
- **주문 API 는 재시도가 위험하다.** 응답을 못 받았을 뿐 체결됐을 수 있다.
  재시도 전 반드시 주문 조회로 상태를 확인한다
- 연속 실패 시 킬스위치 연동

### 대사(reconciliation)
- **매일 증권사 잔고와 로컬 포지션을 대조한다**
- 불일치 시 즉시 킬스위치 발동
- 대조 결과를 리포트에 포함
