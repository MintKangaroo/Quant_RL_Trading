# 베타 — 표본을 늘린 규제 랭커 (2026-09-03, 사용자 요청 · 회차 미차감)

질문 하나: **표본을 5배(국장+미장 합침)로 늘리고 규제를 세게 걸면, 데이터로 배운 결합이 손으로 정한 부호를 이기는가.**
랭커 A·B(국장 300세션)는 졌다. 그 실패 원인이 "표본" 이라면 합치면 달라져야 하고, "정보" 라면 합쳐도 같다.

## 데이터
- 공통 공간 = Analyst 점수 6개(chart · event · flow(kr/us) · fundamental · regime · risk), 시장별·세션별 z. 미장엔 34피처
  패널이 없어 점수 공간이 공통분모다. 시장 원핫 1개.
- 국장: `data/_diag/scores-*-KR.pkl` 271세션(2025-05-21~2026-06-30). 미장: `data/ic-history-us/scores-*.parquet` 508세션
  (2024-06-11~2026-06-22, event 는 SUE v0.2, flow_us 는 잔고 v0.1). 타깃 h5 z(국장 `targets-KR-h5.pkl`, 미장 ic-history targets).
- 홀드아웃(2026-07~) 안 연다.

## 모델 (고정)
| 변형 | 규칙 |
|---|---|
| RIDGE-KR / RIDGE-POOL | 릿지(λ=10, 절편 포함), 국장만 vs 합침 |
| GBM-KR / GBM-POOL | LightGBM 잎 7 · min_data 2,000 · lr 0.03 · 300 라운드 · bagging 0.8 · L2 1.0 (랭커 B 와 같은 규제) |
워크포워드: 국장 판정 블록 = 랭커 B 와 동일(확장창 ≥150세션, 20세션 예측, 퍼지 5). POOL 은 같은 시점까지의 미장 행을 학습에 더한다.

## 판정 (국장 블록에서, 랭커 B 와 동일)
① ΔIC(h5) vs fundamental NW t ≥ 2 ② 상위 24 h5 수익 ≥ 대조 ③ 최악 블록 Δ ≥ −0.03. 미장 블록도 같이 적는다(참고).
**핵심 비교는 KR 단독 vs POOL** — 표본이 원인이면 POOL 이 KR 을 뚜렷이 이겨야 한다.

## 결과 (2026-09-03) — 넷 다 **기각**. 표본 5배는 배운 모델을 "룰의 천장" 쪽으로 올렸을 뿐 넘기진 못했다

```
국장 판정 100세션           IC        ΔIC vs fund(+0.0764)   상위24        최악 블록
RIDGE-KR    −0.0194 (t −1.2)   −0.0958 (NW t −4.62)   +0.006 / +0.018   −0.162
RIDGE-POOL  +0.0410 (t +3.2)   −0.0353 (NW t −3.49)   +0.015 / +0.018   −0.070
GBM-KR      +0.0627 (t +2.8)   −0.0137 (NW t −0.54)   +0.239 / +0.018   −0.097
GBM-POOL    +0.0588 (t +2.4)   −0.0176 (NW t −0.63)   +0.208 / +0.018   −0.119
미장 판정 블록: fund +0.0502 · POOL 변형이 KR 단독보다 낫지만(RIDGE +0.016, GBM +0.032) 역시 fund 미달.
```

- **표본이 도움은 됐다**: 릿지가 국장 단독 −0.019 → 합침 +0.041, 미장에서 GBM −0.050 → +0.032. 국장 300세션만으론
  선형 결합조차 잡음을 배웠고, 합치면 잡음이 줄어 **룰이 이미 있는 자리**로 올라온다.
- **그러나 천장은 그대로**: 최고 변형(GBM-KR/POOL) IC 0.06 으로 fundamental 0.076 에 못 미치고 ΔIC 는 음수. 상위24
  지표(+0.24)는 어제 확인한 대로 꼬리 잡음이라 판정 지표가 아니다.
- 결론: 랭커 실패의 원인은 "표본" 만이 아니라 **정보**다 — 같은 6개 신호를 어떻게 결합해도 손으로 정한 부호 하나짜리
  fundamental 을 못 이긴다. DRL 재개 트리거([[drl-when-information-sufficient]])는 그대로 "새 정보원 통과" 다.

## 심층 진단 D1~D7 (2026-09-03, `tools/trial_pooled_deep.py` · `tools/trial_pooled_rank.py`) — **원인은 목적함수였다**

| 진단 | 결과 | 읽는 법 |
|---|---|---|
| D1 피처별 IC (국장 판정 100세션) | fundamental +0.076 · risk +0.071 · event +0.045 · regime **−0.065** · chart/flow ≈ 0 | 정보는 fundamental·risk·event 셋, regime 은 **반대 방향으로** 유의 |
| D2 치팅 선형(수익률 MSE) | **0.054 < fund 0.076** | 판정 구간을 보고 맞춰도 단일 피처보다 낮다 → 최소제곱이 IC 를 최대화하지 않는다 |
| D3 표본 곡선 10→100% | 0.044·0.058·0.052·0.059 | 평평. 데이터 양은 원인이 아니다 |
| D4 h20 라벨 | GBM 0.110 대 fund 0.131 · 릿지 −0.033 | 잡음 적은 라벨도 MSE 목적이면 못 배운다 |
| D5 잔차 학습(fund 앵커) | ΔIC −0.007 (t −0.3) | fundamental 위에 나머지가 더하는 정보 ≈ 0 — 8/25 한계기여와 일치 |
| D6 미장→국장 전이 | 릿지 0.079 (ΔIC +0.003) · GBM 0.005 | 다른 시장으로 배우면 잡음을 못 외워 룰과 동률, 비선형은 전이 안 됨 |
| **D7 순위 타깃(rank-gauss)** | 치팅 선형 **0.104** · RIDGE-KR 0.078(Δ+0.001) · RIDGE-POOL 0.090(Δ+0.013, t 0.9) · **GBM-KR 0.103 (Δ+0.026, NW t 2.37)** · **GBM-POOL 0.105 (Δ+0.028, NW t 2.88)** | 타깃·피처를 일별 순위 정규분위로 바꾸자 천장이 룰 위로 올라오고, 워크포워드 GBM 이 룰을 유의하게 이긴다 |

**원인 분석.** 랭커 A·B·합침 1차가 진 이유는 표본(D3)도 정보(D5 는 fundamental 위 추가 정보가 없다고 말하지만 D7 은
결합 방식으로 +0.026 이 나온다 — 즉 "정보가 없다" 가 아니라 "MSE 로는 못 꺼낸다")도 아니라 **학습 목적함수**였다.
평가는 일별 Spearman IC 인데 학습은 풀링된 수익률 z 의 최소제곱이었다 — 꼬리 큰 날·종목이 손실을 지배해 fundamental
가중치를 깎고(D2 가중치 +0.014) regime 에 끌려갔다. 순위 정규분위로 바꾸면 최소제곱 = 일별 순위상관 최대화가 되어
같은 모델·같은 규제·같은 표본으로 결과가 뒤집힌다. 랭커 B 결론("데이터로 가중을 배우는 것 자체가 부호보다 못하다")은
**틀렸다** — 목적이 틀렸던 것이다.

**주의.** D7 은 진단이지 사전등록 시행이 아니다(변형을 보고 골랐고, 최악 블록·상위24 기준을 안 쟀다). 채택은 아래
등록을 통과해야 한다. 또 하나: 모델이 regime 의 부호를 뒤집어 쓰고(가중치 −0.057) risk 를 알파로 쓴다 — 룰에선
risk 가 제약이다. 랭커 피처로는 정당하지만, 합성점수에 넣을 때 이중 계산을 피하려면 랭커를 **fundamental 을 대체하는
알파 Analyst** 로 두어야 한다(risk 제약은 그대로).

**다음 행동(가이드).**
1. **시행 L 사전등록**: "순위 목적 GBM 랭커" — 타깃·피처 rank-gauss, GBM 잎 7·min_data 2,000·lr 0.03·300라운드, 학습 =
   국장+미장 합침(GBM-POOL). 기준은 랭커 B 와 동일(ΔIC t ≥ 2 · 상위24 ≥ 대조 · 최악 블록 ≥ −0.03) + 미장 판정 블록에서도
   ΔIC ≥ 0. 통과하면 `ranker` Analyst(관찰 모드) → 한계기여 가중 → shadow → 모의계좌.
2. 통과하면 **DRL 재개 트리거 ①에 해당**한다(새 정보가 아니라 새 결합이지만 fundamental 위 ΔIC t ≥ 2). 그때 RL 상태값에
   랭커 점수를 넣는 설계를 제안한다.
3. 병행: 목적함수 정렬은 RL 에도 똑같이 적용된다 — 배분 RL 의 보상이 "포트폴리오 수익" 이었고 그것도 꼬리가 지배한다.
   RL 재개 시 보상을 순위·IR 기반으로 바꾸는 것이 첫 설계 항목.
