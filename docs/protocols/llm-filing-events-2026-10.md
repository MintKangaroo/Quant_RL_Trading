# 사전등록 — 시행 L1: LLM 공시 정보 추출 (2026-09-28 · family `sources` · 전방 판정만)

설계: [ai-full-stack.md §4](../design/ai-full-stack.md) · 과적합 규율 §2 전부. 코드: `quant_rl_trading/collectors/llm_filing_events.py`,
`tools/extract_filing_events.py`, 표 `filing_events`.

사용자 비용 승인(Haiku 4.5 · 월 $20, 2026-09-28) → 축적 시작일 기입(2026-09-29) → 해시 고정(2026-09-28) 끝. 크론 매일 03:07.

## 왜

지금 공시는 두 방식으로만 쓴다: **제목 분류의 건수**(`event` Analyst 의 `FILING_SIGNS`)와 **유형별 정규식 파서**(G8 잠정실적·G12 손익구조·
G13 공급계약). 건수는 BA(9/27 기각)에서 보았듯 "어떤 회사인가"(스타일)를 말하고, 파서는 유형마다 따로 짜야 하고 **방향**(좋은 조건의 증자인가,
채무상환용 사채인가, 해지가 소규모인가)을 못 읽는다. LLM 은 원문 한 건을 유형을 가리지 않고 **같은 틀**(사건 종류·방향·크기·비교 기준 대비·확신)로
옮긴다. X(9/25 기각, 원문 임베딩)의 교훈 ③ "유형이 아니라 **내용의 좋고 나쁨**을 담는 표현이 필요하다" 에 대한 직접 답이다.

## 누수 — 판정이 전방만인 이유

LLM 은 학습 시점까지의 세상을 안다. 과거 공시를 읽히면 "이 회사가 뒤에 어떻게 됐는지" 가 답에 섞일 수 있고, 그것을 막을 방법이 코드에는 없다.
그래서 장치 셋을 겹친다:

1. **`observed_at` = 추출 시각**(공시 목록 관측 시각을 옮기지 않는다 — G8·G12·G13 의 파서와 반대 규칙). 과거 공시를 오늘 뽑은 행은 과거 as_of
   조회에 **한 행도 안 잡힌다**. 판정 창이 쓰는 모든 조회가 `store.get(as_of=...)` 를 지나므로 백필분은 과거 판정에 못 들어간다.
   고정: `tests/collectors/test_llm_filing_events.py::test_backfilled_old_filing_is_invisible_to_past_as_of`.
2. **접수일 하한**(`forward_only(start=축적 시작일)`): 판정 시점(2027)에서는 오늘 백필한 행도 observed_at ≤ as_of 라 보인다. 그래서 피처는
   **축적 시작일 이후 접수된 공시만** 쓴다. 고정: `test_forward_only_drops_backfill_even_when_visible`.
3. **캐시 행도 observed_at = 추출 시각**(리드 결정 2026-09-28). `replay/cache.AgentCache` 는 observed_at 을 키 시각(접수일)으로 적어
   과거 as_of 에 LLM 출력이 보이게 되므로 쓰지 않고, 같은 `agent_cache` 표에 추출 시각으로 직접 적는다. 재호출 방지는 시각이 아니라
   **키**(스키마+PROMPT_HASH · 원문 지문+제목)로 찾는다. 피처는 `load()`(= `filing_events`)에서만 읽는다.
   고정: `test_cache_rows_are_invisible_to_past_as_of` · `test_cache_is_found_by_key_on_a_later_day`.

입력에 날짜·종목코드는 주지 않는다(원문 안의 회사명·날짜는 어쩔 수 없다 — 그래서 위 셋이 본 장치다).

## 축적

- **시작일**: **2026-09-29**(접수일 기준, KST) — 사용자 승인 2026-09-28. 코드 상수 `FORWARD_START` = `forward_only` 의 start. 정정은 **원공시** 접수일로 판단한다.
- **판정 가능 시점**: 시작일부터 **60세션 이상**(2026-09-29 시작이면 2027-01 초). 60세션 미만이면 판정하지 않는다(보류 — 시행 미소진).
- 크기 추정(v3 범위): 최근 30일 LLM 호출 384건(유상증자 221·사채 95·자사주 67·G8 밖 잠정실적 소수), 달마다 약 400~520건 — 손익구조변동이 빠져 2·3월 시즌 봉우리가 없다. 최대주주변경은 원문 수집 확장 뒤 달 +90~105건.

## 피처 — 사건형 3개 이하 (6차 규약), 측정 전 고정

세션 s 에 대해 **s 개장 전 observed_at** 이고 **접수일 ≥ 시작일**인 `status='ok'` 행만. 창은 접수일 기준 **20세션**:

| 피처 | 정의 |
|---|---|
| `l1_dir_20` | 창 안 사건들의 direction 합(−1/0/+1). confidence 로 가중하지 **않는다**(모델이 스스로 매긴 값 — 과신이 그대로 실린다) |
| `l1_mag_20` | 창 안 **가장 최근** 사건의 direction × (그 magnitude 의 **같은 단위 안** 백분위, 0~1). 단위가 none 이면 0. 단위가 다른 크기를 한 줄에 세우지 않는다 |
| `l1_surprise_20` | 창 안 vs_prior better 건수 − worse 건수 |

사건은 **사건 키마다 최신 정정 하나**(`load()`), 창은 **원공시 접수일** 기준 — 정정은 새 사건이 아니다. 사건 없는 종목은 세 값 모두 0(결측 0 규약). 개별 피처 사후 선택 금지 — 셋을 한 번에 넣고 뺀다.

## 정확도 확인 — 판정 전 관문 (리드 결정 2026-09-28)

표본 6~10건은 정확도를 판정하기엔 너무 작다(한 건이 17%p). 그래서 **축적 첫 4주**(2026-09-29 ~ 2026-10-26 접수분)의 `status='ok'`
행에서 **무작위 30건**(시드 고정 0, `magnitude_source` 로 층을 나누지 않는다)을 뽑아 원문과 **수기 대조**한다. 채점표는 표본 때와 같다:
크기·단위·칸이 원문과 맞는가, 방향이 수용 가능한가. `failed`·`too_long` 행 비율도 같이 적는다.

- **오답률 > 20%**(30건 중 7건 이상 — 크기·칸 오답 또는 방향이 원문과 반대)면 **판정 전 중단**: 축적 크론을 멈추고, 원인(유형·칸)을 복기해
  새 지문(프롬프트·코드 규칙)으로 **처음부터** 다시 쌓는다. 그때까지 쌓인 행은 판정에 쓰지 않는다.
- 오답률 ≤ 20% 면 축적 계속. 대조 결과(30건 표)는 이 문서에 붙인다 — 판정 수치(수익)는 보지 않는다.
- 이 관문은 수익과 무관하다(스키마 품질 점검) — 사전등록 판정 창을 소비하지 않는다.

## 판정 — 두 단계

랭커 재학습(6차 틀)은 **학습창에도 피처가 있어야** 한다 — 전방 축적 60세션으로는 확장창 ≥150 + 판정 100세션이 안 나온다. 그래서:

### 단계 A — 60세션 뒤, 학습 없는 관문 (계속 돈을 쓸 가치가 있나)

대조 **C1 = 같은 재료에서 LLM 만 뺀 것**(§2.3 규칙 13): direction 대신 제목 분류 부호(`event` Analyst `FILING_SIGNS`), magnitude 대신
**0**(L1 대상은 파서가 없는 유형이라 규칙 크기가 없다 — 유상증자만 코드 계산 비율을 쓸 수 있으나 그것은 L1 의 입력이기도 해 C1 에서 뺀다),
vs_prior 대신 0. **같은 공시 집합·같은 창**. G12·G13·G8 은 각자의 6차 묶음으로 따로 판정한다 — L1 은 그 위의 **파서 없는 유형의 몫**을 묻는다.

| | 기준 | 값 |
|---|---|---|
| A① | 사건 보유 종목(창 안 사건 ≥1) 안에서 세 피처 등가중 합성의 세션별 횡단면 IC(h5, 초과수익 z), **실전 랭커 점수로 잔차화한 뒤**, NW t(lag 4) | ≥ 2.0 |
| A② | 같은 통계의 L1 − C1 일별 차이 | 평균 > 0 |
| A③ | **성향 점검(BA 교훈)**: 합성 피처와 β(60일)·log 시총·B/M·배당 여부의 세션별 순위상관 평균을 기록. 어느 하나라도 \|ρ\| > 0.3 이면 A① 을 그 성향까지 잔차화해 다시 재고, 그것도 ≥ 2.0 이어야 한다 | 기록 + 조건부 재판정 |

셋 다 통과 → **축적 계속 + 단계 B 대기**. 하나라도 실패 → **축적 중단**(크론 제거), 이 형태로 다시 열지 않는다(새 재료·새 등록 필요).
주 시장 국장만. 두 국면(박스·급등) 판정은 60세션으로 불가 — 국면별 값은 **기록만**.

### 단계 B — 250세션 뒤, 6차 틀 그대로

축적 250세션(학습 150 + 판정 100)이 되면 6차 공통 고정(모델·워크포워드·관측 시각·결측 0·3시드)과 기준 넷(①ΔIC t≥2 · ②상위 24 z-수익 처리≥대조 ·
③최악 블록 ΔIC ≥ −0.03 · ④다른 시장 ΔIC ≥ 0 — 미장은 재료가 없으므로 ④ 는 "미장 IC 가 떨어지지 않음")으로 판정한다. 대조는 그 시점 실전 랭커 피처.
채택은 **후보**일 뿐이고 투입 사다리(§2.4: 금고 → shadow 20세션 → 모의 → 실계좌)를 한 칸씩 오른다.

## 하지 않는 것

- 과거 공시 백필로 판정하지 않는다(누수). 백필은 스키마 점검·비용 측정용 기록일 뿐이다.
- 프롬프트·모델을 축적 도중에 바꾸지 않는다. 바꾸면 새 `PROMPT_HASH` 로 **처음부터** 쌓는다.
- confidence 를 가중·필터에 쓰지 않는다. evidence·event_type 은 진단·해설용이다.
- 보상·판정 식에 넣지 않는다(불변식 8). RL 상태값에는 과거 이력이 생긴 뒤에만(CLAUDE.md).
