# 마일스톤

원칙: **M3까지는 RL 없이 돌아가야 한다.**
RL이 없으면 아무것도 안 되는 구조로 만들지 않는다. RL은 작동하는 시스템 위에 얹는 것이다.

각 마일스톤의 완료 기준이 전부 켜지기 전에는 다음으로 넘어가지 않는다.

### 완료 기준

- [x] 국장/미장 IC 별도 측정 완료 — **미장은 chart·risk·regime 3개로 판정한다**
- [x] News·SNS 거부 성적표 집계 시작 — **파이프라인 가동을 기준으로 한다**

> 백테스트 IC가 0.15처럼 나오면 재능이 아니라 버그다. 먼저 누수를 의심할 것.

| **event** | **+0.0356** | — | 1.0 |
| chart | +0.0014 | +0.0145 | 0.0 |

| flow_kr | −0.0011 | — | 0.0 |

KR 2,787종목 · US 6,440종목. 통과 4개(risk 는 두 시장), 관찰 모드 5개.

**risk 가 두 시장에서 통과한 것이 이 마일스톤의 실질이다.** 한 시장에만
맞는 신호는 그 시장 표본에 사후적으로 맞춘 것일 수 있다. 시장을 바꿔도
남는 신호는 그 의심이 한 단계 줄어든다.

**chart 는 두 시장 모두 미달이다.** KR +0.0014 는 `low_volatility` 를 뺀 뒤의
정직한 숫자다 — 그 피처는 risk 의 것이었고, 그걸 넣은 채 잰 +0.0197 은 빌린
성적이었다. chart 고유 피처 여섯은 피처별 IC 에서 전부 잡음으로 나왔고,
가장 큰 가중치(25%)를 받은 momentum_20 의 IC 가 정확히 0.0000 이었다.

유력한 원인은 **타깃과 피처의 시간 축이 어긋난 것**이다. 타깃은 5일인데
(`ic.HORIZON_DAYS`) momentum_20·60 은 몇 달 단위 현상을 본다. 고칠 방향은
5일 축 피처로 교체하는 것이지 가중치 조정이 아니다.

**지금은 하지 않는다.** 표본이 KR 300세션 하나뿐이라, 새 피처를 열 개 시도해
하나가 통과하면 그건 신호가 아니라 열 번 던져 한 번 맞은 것일 수 있다. 실전
데이터가 쌓인 뒤 새 표본으로 본다.

regime·flow_kr 은 폴드 부호가 시기에 따라 뒤집힌다 — 약한 신호가 아니라
잡음이다.

**event 는 DART 공시 574,829건이 들어오며 피처가 2개 → 6개가 됐다**
(buyback·dividend·contract·dilution·distress + maturity). +0.0333 → +0.0356.
같이 드러난 것이 `no_halt` 였다 — 실측 상수(고유값 1개)라 IC 가 nan 인데
가중치의 45% 를 들고 있었다. 뺐고, `combine` 이 분산 0 인 피처를 자동으로
제외하게 했다.

**상수 피처를 빼도 IC 는 바뀌지 않는다** — IC 가 순위상관이고 상수 열은
점수를 상수배 할 뿐이라 순위가 그대로다(실측: 폴드까지 소수점 일치). 달라지는
것은 **점수의 크기**이고, 그건 M3 Selector 가 Analyst 들을 합칠 때 쓴다.

**미장 수치는 생존편향 위에 있다.** LS 가 상폐 종목 시세를 주지 않아
명단에 상폐 종목이 0건이다. 실제보다 후하게 나온다는 전제로 읽는다
(`collectors/us_universe_panel.py`).

### 판정 기준을 좁힌 두 곳 (2026-08-13 확정)

**미장 IC 는 3개만 잰다.** fundamental 은 미장 재무가 없고, event 는 미장
이벤트가 없고, flow_us 는 입력이 구조적으로 0건이다 — 미국에는 투자자별
순매수 공시 제도 자체가 없다(`analysts/flow_us.py` 모듈 docstring). 없는
데이터로 잰 IC 는 "안 먹혔다" 가 아니라 **"잰 게 없다"** 이므로, 재지 않는
것이 재서 0 을 적는 것보다 정직하다. 붙일 자리(short interest·13F·ETF
자금흐름)는 남겨 뒀고, 그건 M2 가 아니라 별도 수집기 작업이다.

**News·SNS 성적표는 "파이프라인 가동" 을 집계 시작으로 본다.** 배관은 끝까지
검증됐다 — 뉴스 40건 → 패턴 4건 → LLM 4건 전부 기각. `verdicts` 0건은
고장이 아니라 **거부할 사유가 없었다는 정답**이다. 실제 차단 기록이 쌓일
때까지 기다리는 기준은, 나쁜 뉴스가 나야만 마일스톤이 닫히는 이상한 조건이
된다. 대신 **거부가 처음 기록되는 날 배관을 한 번 더 확인**한다 — 0건이
정답인 구간에서는 고장과 정답이 같은 모습이기 때문이다.

### 실매매 전에 반드시 있어야 하는데 **아직 없는 것** (2026-08-14 확인)

1. **주문 전송 경로가 없다.** `executor/` 는 목표비중을 주문으로 바꿔 창고에
   적는 데서 끝난다. `place_order`·`submit_order`·`CSPAT*` 호출이 한 군데도
   없다. `ls_client.py` 에 `PATH_ORDER` 와 체결 응답코드(00039·00040·00463)가
   LS_KR 에서 이식돼 있지만 **부르는 함수가 없다.** 바닥재만 깔린 상태다.
   부분체결·재호가·취소·멱등 client order id 가 전부 여기에 딸려 온다.
2. **모의투자로는 우회할 수 없다.** `ls_client.py:81` — paper 모드에서 잔고
   (t0424)와 주문(CSPAT*)은 LS 가 막는다. 주문 배선 검증에는 실전 appkey 가
   필요하다.
3. **shadow 가 체결 0 이다.** 2026-08-13·14 이틀 다 후보 24 · 주문 12 ·
   체결 0 이고 NAV 가 10,000,000 에 고정돼 있다. 무사고이긴 하지만 **손익
   경로가 한 번도 안 돌았다** — 날짜만 채우면 10일이 차도 검증이 아니다.
4. **벤치마크가 계산되지 않는다.** `accounting.nav.blended_benchmark()` 는
   구현돼 있으나 **어디에서도 호출되지 않아** `benchmark_index` 가 실전·데모·
   테스트 픽스처 전부 null 이다. 초과수익도 벤치마크 낙폭도 근거가 없다.
   config 는 `KOSPI_TR`·`SPX_TR`(총수익지수)을 요구하는데 창고에는 가격지수
   (KRX 100·KRX 300·SP500)뿐이고, 가격지수를 쓰면 배당수익률만큼 가짜 알파가
   생긴다. 총수익지수 수집처를 찾는 것이 선행 과제다.
5. **섹터 상한이 걸리지 않는다.** 수집은 붙였으나(`sectors` 테이블) KRX
   일별매매의 `SECT_TP_NM` 은 업종이 아니라 **KOSDAQ 소속부**다 — KOSPI 는
   942 종목 전부 빈 문자열이고 KOSDAQ 만 우량기업부·벤처기업부 등으로 갈린다.
   그걸로 건 상한은 상관 분산이 아니라 시장 등급 분산이라, 켜면 "분산되고
   있다" 는 착시만 생긴다. 진짜 업종 분류(KRX 업종분류현황)를 받기 전까지 끈다.

2. **워밍업 없이는 매매가 0건이다.** confidence 가 60거래일 롤링 IC 라

**하루당 198초** (2026-08-14 실측). 처음 잰 값은 432초였고, 파티션 하한

`lookback` 을 줘도 5년 파티션을 전부 열고 있었다(`71e4316`). 대시보드도 같은
원인으로 14.7초 → 2.4초가 됐다.

남은 198초 중 **190초가 Analyst 계산**이다. 가중치 진화(개체 64 × 세대 40)와
M4 학습은 여기를 더 줄여야 가능하다.

### 이 구간에서 잡은 결함 — 셋 다 증상이 "후보 0건" 이었다

1. **confidence 가 못 잰 것을 0 으로 두고 있었다.** 합성이
   `Σ(w·score·conf)/Σ(w·conf)` 라 분모가 0 이 되어 후보가 통째로 빈다.
   신호 13,746행이 쌓였는데 아무것도 못 골랐다 (`0409951`)
2. **세션 시각(15:40)이 신호 공표(16:00)보다 일렀다.** 결정이 언제나 전날
   신호로 내려가 하루가 통째로 밀렸다 (`cfebd3c`)
3. **장중 실행이 미래 시각 주문을 만들었다.** 그 주문은 어떤 조회에서도
   안 보인다 — 창고에는 있는데 화면에는 없는, 가장 헷갈리는 고장이다

**진화를 Session 뒤로 미룬 것은 의도다.** selector.md §3 이 "평가는 실제
백테스트로 한다. 점수 상관만으로 평가하면 실제로 못 사는 종목으로 적합도를
얻는다" 고 못 박았고, 백테스트 루프는 Session 위에서만 돈다. 순서를 지키면
설계가 금지한 방식으로 만들게 된다.

> M4에서 학습이 안 되면 재정식화를 반복하지 않는다.

> 원인을 분리해 다시 접근한다. 선행 프로젝트는 9차까지 끌고 가다 폐기했다.

## 중단 기준

각 마일스톤에 시한을 둔다. 시한을 넘기면 접거나 방향을 바꾼다.

- M4에서 RL 재정식화 **3회 실패** → M3 룰 베이스라인 유지, RL은 별도 트랙으로 분리
- Analyst가 6개월간 하나도 IC 0.03을 못 넘김 → 피처·타깃 설계를 원점 재검토
- 실전 12개월간 shadow IR이 지속적으로 음수 → 프로젝트 종료 검토

선행 프로젝트가 실패한 결정적 이유 중 하나는 **중단 기준이 없었다는 것**이다.
